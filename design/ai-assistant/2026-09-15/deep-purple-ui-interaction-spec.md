## 3. 推荐整体骨架

采用“窄导航 + 联系人列表 + 当前对象工作区”，同一时刻只处理一个对象。

以 1440 × 900 为设计基准：

| 区域 | 建议大小 | 内容与规则 |
| --- | --- | --- |
| 深色导航 | 184–200 px | 自动回复、主动聊天、运行记录、模型设置；账户信息置底 |
| 顶栏 | 56–64 px 高 | 当前微信、AI 实际状态、总开关；模型异常显示可操作入口 |
| 页面标题 | 64–80 px 高 | 小型深紫标题区，最多一行辅助文案 |
| 联系人列表 | 252–280 px | 联系人/群聊、搜索、过滤、滚动列表、批量操作入口 |
| 对象工作区 | 剩余宽度，主要表单最大 880 px | 对象摘要、策略卡、记忆摘要、回复要求、底部保存 |
| 内容留白 | 外边距 24 px，组间 16–24 px | 保留清晰分组，减少卡片内部再套大卡片 |
| 控件 | 输入与按钮 40–44 px 高 | 正文 14–16 px、辅助说明 12–13 px、标题 22–26 px |
| 保存栏 | 60–64 px 高 | 固定在工作区底部；预留同等底部空间，避免遮挡内容 |

窗口不足 1200 px：主导航收为图标栏并提供名称提示；联系人列降至 224 px。不足 900 px：联系人列表与对象详情分屏，返回时保留搜索、筛选和滚动位置。长内容按需滚动，不能靠缩小字号塞满首屏。

## 4. 信息分层

| 模块 | 第一层直接展示 | 点击后展示 | 入口 |
| --- | --- | --- | --- |
| 联系人列表 | 名称、头像、实际运行状态；最多一个必要状态标签 | 完整名称和对象详情 | 点击联系人 |
| 对象摘要 | 当前对象、个人/群聊、开启/关闭/暂停、是否沿用默认策略 | 配置来源及完整说明 | 状态说明/配置详情 |
| 关系与记忆 | 已有明确关系/称呼摘要，最多两行；没有则显示“尚无记忆” | 完整双方记忆、编辑、最近学习结果 | 查看与编辑 |
| 回复策略 | 自动回复、多轮交流、智能判断，主从关系明确 | 延迟、连续回复上限、边界等已有高级参数 | 高级设置 |
| 聊天风格 | 当前风格名称、来源、学习入口 | 完整风格说明、自定义编辑、学习范围、结果预览 | 编辑风格/学习风格与记忆 |
| 回复要求 | 简短要求，可直接编辑，默认 3 行 | 更长文本展开；允许信息、边界等低频内容 | 展开/高级设置 |
| 默认回复范围 | 当前范围的紧凑摘要 | 范围选择和影响说明 | 默认规则 |
| 运行异常 | 影响当前对象的原因和下一步，例如“发送待核对” | 核对记录或连接详情 | 去核对/检查连接 |

一级信息的判断规则：影响“对象是谁、当前会不会回复、按什么规则回复、现在要处理什么”的信息直接展示。解释、历史、长文本和低频参数点击展示。异常和未保存状态不能隐藏在高级设置中。

“关系摘要”优先复用已有明确记忆，不擅自新增亲密度评分、联系人分类系统或模型推断的关系。若当前数据不能可靠表达关系，首层仅显示记忆摘要，结构化关系字段另立待选项。

## 5. 自动回复交互

1. 进入页面恢复上次对象；第一次进入显示选择提示。选中联系人只查看/编辑，不开启自动回复。
2. 对象顶部同时呈现配置和实际状态。例如“自动回复已配置 · AI 总开关已关闭”，避免开关亮着却让用户误以为正在回复。
3. 对象开关、风格、记忆和回复要求统一作为草稿；修改后底栏显示“未保存”。点击“保存设置”成功后再显示生效状态。保存失败保留草稿。
4. AI 总开关属于全局即时操作，明确标注作用于当前微信；点击后等待服务确认，失败回退显示，不隐式提交对象草稿。
5. 关闭对象自动回复时保留多轮交流/智能判断原值，子项禁用；再次开启可恢复。
6. 切换对象时按当前微信与对象分别保留草稿，列表给未保存标记。关闭页面或切换微信时若有草稿，提供保存/放弃/留在当前页，避免串账号或静默丢失。
7. 学习通过单层侧边面板完成：选择范围 → 学习进度 → 预览风格与记忆 → 选择采用内容 → 写入对象草稿 → 保存。支持取消与重试，手动记忆不能被重新学习静默覆盖。
8. 抽屉最多一层；长表单用抽屉，短确认用弹窗，短高级参数用就地折叠。关闭后恢复焦点和页面位置。
9. 暂停/接管/恢复沿用真实状态；发送结果待核对时优先提供核对入口，不提供可能造成重复发送的一键重试。

## 6. 群聊

- 沿用同一工作区骨架，回复方式替换为“@我时回复、@所有人时回复、AI 实时回复”。群设置与个人默认范围明确分开。
- 首屏显示当前触发方式和是否暂停；群记忆、风格详情和高级参数折叠。
- 实时回复开启沿用现有确认与说明；取消不能改变已保存状态。个人自动回复的默认设置不能无提示影响群聊。

## 7. 主动聊天

一级界面先展示已保存策略摘要和当前任务：对象数量、聊天目标、风格、发送方式、立即/定时、运行状态。没有策略时显示“配置策略”作为主操作。

配置流程保留完整步骤：选择对象 → 沟通目标与要求 → 聊天风格 → 节奏与时间 → 总览。按内容分步，顶部始终显示对象数量和步骤；返回不丢输入。

完成配置后主操作为“一键发起聊天”或“保存定时聊天”。发起前总览清楚呈现对象、策略、时间和发送模式，操作名称与实际效果一致。

运行中显示已处理/待处理/需接管人数，以及暂停/继续/停止；具体每人进度点击查看。当前自动回复与主动聊天策略保持隔离。

## 8. 模型设置与运行记录

模型设置首层：服务预设、选定模型、连接状态、测试连接、编辑配置。未配置时直接展示必要配置，不隐藏在空的摘要后。编辑时提供 API 地址、协议、遮罩 Key、模型拉取与手填；常见预设和完整自定义均保留，不静默改模型 ID。修改配置后旧测试状态失效；测试和保存分别反馈结果。

运行记录首层：时间、对象、触发方式、结果，提供对象/结果/时间过滤。点击记录打开详细原因与可用处理操作。仅在已有记录支持时展示相关内容，不因 UI 设计擅自新增聊天正文持久化。待核对、未发送、已发送必须区分。
