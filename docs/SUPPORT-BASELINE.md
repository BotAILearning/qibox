# fnOS 最低支持目标与依赖裁剪边界

决策日期：2026-10-18。最低支持目标为 **fnOS 1.2.0401**，支持原生 x86_64 与 ARM64；`config/product.json` 的 `minOSVersion` 原已为 `1.2.0401`，继续作为安装清单来源。选择此版本是保留当前所用开放 API 能力并覆盖后续版本的支持策略，不是所有版本、设备均已通过的结论。

## 选择依据

飞牛官方开发文档 2026-07-31 更新日志说明，新增开放 API 要求 fnOS 1.2.0401 及以上；相应飞牛 App 宿主要求 1.34.0 及以上。栖盒已有文件授权等集成，不为降低版本号牺牲这些功能。资料来源：<https://developer.fnnas.com/docs/update-log/>，2026-10-18 从官方原站 HTTP 200 获取并核对；不要用第三方镜像代替依赖兼容性证据。

最低版本限定为原生、未篡改的受支持 fnOS 环境。不兼容更老系统、非飞牛系统和人为删除/替换系统关键组件的环境；不得为这些范围携带完整重复系统。更高版本仍需组件检测、兼容性校验及自检，不按版本字符串直接进入就绪。

## 真正裁剪的约束

- 最低版本号只是平台边界，不能单独证明某个 Python、动态库、工具或字体必定存在、ABI 相容。
- 每个拟从 FPK 删除的组件必须形成证据：官方最低版本系统或正式镜像中的组件来源与版本、文件/符号/动态依赖、两架构差异、功能依赖和测试结果。为后续系统版本变化设计重新检测和失败处理。
- 确认由受支持系统保证提供且兼容的组件，从 FPK 删除重复副本；不能只是运行时链接系统，而仍完整随包携带同一套后备，然后计算下载节省。
- 支持范围内仍可能缺失或不能确认兼容的组件继续提供必要私有后备。原生输入法、中文及表情字体、虚拟显示、远程桌面、音频媒体、文件选择等按真实依赖保留；FFmpeg 工具与媒体库须保持一致可用。
- Node.js 使用飞牛官方应用依赖；不安装系统软件包，不修改系统库，不借用无关应用的私有目录。运行组件完整随包，不增加外部下载源。
- 系统组件异常或版本不兼容时不能假就绪；新环境通过校验和功能自检才切换，保留已有可用环境与资料。检测失败及恢复限制应有业务可理解的说明。

## 证据与待验收

目前主测试机实测系统为 **fnOS 1.2.0800 / Debian 12 / x86_64**，于本轮通过严格 SSH 核实系统标识和设备身份。具体设备信息仅留在已忽略的本地记录。已有真实结果仅对应实际测试的系统、组件及样本，不等于 1.2.0401 真机验收。

fnOS 1.2.0401 是最低支持目标，最低版本设备验收仍待完成。不得降级、重装或清空当前主测试机来凑最低版证据；可先完成官方最低版组件核对与隔离验证，虚拟/模拟结果必须标明。若最终缺少最低版实机条件，集中报告确切缺项；不能把 1.2.0800 的结果改名，也不能停止其余安全裁剪和主测试机最终包回归。

ARM 尚无真机，完成独立资源构建、ELF/依赖/符号/版本要求检查和自动测试；不能套用 x86 清单或宣称 ARM 动态运行已通过。
