# 页面比例与操作层级验收

适用于栖盒网页与 AI 工作台的桌面和手机布局。按钮是否占满一栏，取决于它是否是该区域的主要提交操作；添加、刷新、导入等辅助入口随内容定宽。空状态卡片随内容定高，列表可滚动，但不为尚不存在的内容预留大片空白。

## 自动检查

先执行 `npm run build:web`，再执行 `npm run test:ui-proportions`。脚本使用临时的应用、微信联系人和模型桩，在真实浏览器排版后检查：

| 页面与状态 | 宽度 | 检查 |
| --- | --- | --- |
| 应用市场，未安装 | 320、390、1024、1440px | 安装为主要操作，导入入口宽度小于卡片 70%；窄屏触控高度；侧栏按内容定高；无横向溢出 |
| 应用市场，已安装 | 390、1440px | 只显示一个主操作；手机为“添加实例”，桌面为“添加到桌面” |
| 自动回复，联系人列表 | 1440px | 批量学习与刷新同排，各自小于侧栏 65% |
| 分析报告，未选和已选联系人 | 320、390、1024、1440px | 添加入口小于卡片 72%、高度至少 44px；空卡片小于 220px；弹窗选人后数量更新；无横向溢出 |
| 学习默认风格，未设置 | 320、390、1024、1440px | 空状态小于 260px；无横向溢出 |
| 批量学习、模型设置、主动聊天、执行记录、系统设置 | 320、390、1440px | 页面没有横向溢出 |

截图和 JSON 结果保存在 `reports/ui-proportions/`。变更页面结构时，应同时检查 390px 和 1440px 截图中的按钮层级、文字换行、留白及页面滚动；几何断言无法替代视觉判断。正式交付还须运行原有 UI 回归，并在 fnOS 安装后重新打开对应页面检查。
