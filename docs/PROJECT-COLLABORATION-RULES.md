# 栖盒项目协作规则

本文件只保存跨任务、长期有效、会改变执行方式的原则。一次性命令、具体需求、临时偏好和过程记录不写入本文件。

## 1. 文档分层

- **本文件**：项目级长期规则。
- **当前任务简报**：本次任务的目标、范围、相关文件和验收标准。
- **任务记录**：过程、测试证据、版本结果和历史结论。

如果一条内容只影响当前任务，就放入任务简报或任务记录。

## 2. 执行方式

- 用户明确下达执行命令时，命令本身即授权，直接按范围执行，不先登记或重复确认。
- 讨论、方案和历史记录只有在用户明确要求执行时，才转为实际修改、测试、打包或部署。
- 一次性执行命令不写入长期规则。

## 3. 上下文与质量

- 每次任务只加载当前任务简报、相关文件和必要的项目事实，不通读全部历史资料。
- 历史方案、重复内容和已失效信息默认归档；未验证结论不得写成已完成。
- 本地修改完，直接上传真机校验。

## 4. 模型分工

- **GPT-6 Astra**：复杂规划、架构、风险、验收标准和高风险复核。
- **GPT-5.6 Luna**：范围明确的定向阅读、局部修改、测试和证据整理。
- Luna 不独立扩大范围、决定复杂架构或宣布真实验收完成。

## 5. 版本与平台

- 版本按 `A.B.C` 管理：普通改动递增 C，较大功能变化才递增 B，A 必须由用户明确指定。

## 6. 规则维护

- 新规则必须长期有效、跨任务适用，并确实改变执行方式。
- 相似规则合并；失效规则归档，不与现行规则并列。
- 无法确认是否仍有效时，不主动加载，回到当前任务重新核对。
