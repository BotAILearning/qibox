# 栖盒整体布局审查与修订

本次从已上线的 0.9.47 开始，依据用户 2026-09-29 提供的分析报告截图，逐页改进信息层级、控件排版与可用宽度。独立工作区保留原开发目录的全部未提交内容，功能和数据契约继续以产品规格为准。

## 采用的标准

- [Carbon 布局](https://carbondesignsystem.com/elements/2x-grid/usage/)：以任务为中心，标题、内容、操作保持可预测的位置；导航和侧栏占用空间后，正文必须重新布局。
- [Carbon 表单](https://carbondesignsystem.com/components/form/usage/)：把相关字段放在一起，标签、帮助文字和主要操作保持清楚的层级。
- [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：窄窗口和缩放后仍应可读、可操作；不能靠把中文挤成竖排来消除横向滚动。
- [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：操作目标需要足够大小和间隔。本项目沿用既有 40px 桌面控件与 44px 触控尺度。

以上是设计依据，不代表对整套产品作出 WCAG 合规认证。

## 初始问题与处理原则

用户截图显示：分析方向的中文逐字换行、右侧时间卡片随正文无意义拉长、主要输入区被多层栏位压缩。源码确认，问题来自视口断点与固定四列相叠加：导航、联系人、内边距和时间栏已经占去大量宽度，方向按钮却仍被均分为四列。通用按钮的任意折行进一步放大了问题。

采用内容区域尺寸决定列数，短标签保持完整，必要时整项换行。保留 QIAPP 的蓝紫色、基础控件和栖盒既有图标，统一页面组合层而非再创建一套基础控件。

## 检查方法

1. 临时示例应用用于视觉审查，使用模拟联系人、模型和桌面；AI 自动发送定时器关闭，发送接口拒绝发送。
2. 窗口至少覆盖 320、390、1024、1180、1200、1280、1366、1440、1920px，重点检查此前漏掉的中间尺寸。检查短标签单行、控件边界、内容区域溢出、空态及有数据状态。
3. 验证联系人选择、分析方向、时间、模型编辑取消、对象设置页签、记录筛选、主动任务编辑和返回，不更改真实账号配置或发送消息。
4. 完成本地回归后生成 FPK，经 fnOS 应用中心升级。安装后重新读取版本、服务、文件哈希和实例状态，再检查实际 NAS 页面。
5. 本地自动化、NAS 页面浏览器检查、实体手机/真实微信通信分别说明。后两项不得从截图或包哈希推断。
