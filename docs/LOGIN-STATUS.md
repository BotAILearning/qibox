# 微信登录状态

桌面卡片使用当前微信原生界面的登录状态，而不是进程是否存活。正常结果为「已登录」「未登录」；首次检查和超过 15 秒没有有效观察时显示「检测中…」，不把未知状态当成已登录。

- 已连接桌面：只在该实例微信窗口被隐藏或最小化时显示「显示微信」；窗口已显示时隐藏此按钮。恢复窗口保留当前桌面连接、文字输入和文件选择桥接。
- 桌面断开或微信停止：按钮为「连接微信」，启动该实例并连接其桌面。
- 原生界面提示重新登录，或本次运行中从已登录转为未登录：按钮为「重新登录」。打开该实例的登录界面；只有原生界面确实存在可见的「重新登录」按钮时才触发该按钮，不点击退出登录、切换账号或登录确认。

`server/login-state.mjs` 保存进程生命周期内的状态，单次检查合并并间隔至少 1 秒，以便新登录后尽快更新卡片；旧进程的异步结果不能覆盖新进程。当前状态不复用自动登录资格、账号目录或保存的凭据证据。

`server/auto-login.py --session` 只检查该实例私有总线上指定的微信进程。跳过列表、文本、文档等内容节点，不记录控件原文。`--login-page` 仅由经过身份、实例归属和 CSRF 校验的主动请求调用。原来的闲时备份资格检测逻辑保持独立。

检测依据是当前官方 Linux 微信的可访问控件。未知客户端布局和检测故障保持未知；检测不是微信服务器提供的在线状态接口。

窗口是否显示由该实例私有 X 显示中的窗口管理器状态判断，按微信进程 PID、窗口类型和 WM_CLASS 过滤；不从桌面是否连接或登录状态推断。探测合并并节流，超过 5 秒的窗口观察返回未知。

全屏按钮随 `fullscreenchange` 同步为「全屏」或「退出全屏」，支持通过按钮及浏览器退出。断线提示层随当前状态双向更新。离开页面、断线、鼠标取消及全屏切换时释放 noVNC 捕获和远端鼠标按钮，取消打开桌面后丢弃迟到的连接结果。
