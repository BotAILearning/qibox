# 栖盒体验与性能优化验收基线

本轮由用户在 2026-10-02 明确启动。基于真机 0.10.20-stable.003 和对应源代码推进，范围为 fnOS；保留所有已支持功能、账号隔离和人工接管规则。以下指标是验收目标，不能用未完成的测试替代结论。

## 体验最高标准与实现方向

| 方面 | 标准 | 优化及验收方法 |
| --- | --- | --- |
| 页面可理解性 | 主任务、当前账号、保存状态一眼可见；选填内容不造成任务压力 | 个人信息紧凑分组；已有内容直接预览；常驻保存入口；不把填写率当成必须完成的任务 |
| 操作效率 | 常用任务就地完成；无重复填写和无效确认 | 保留未保存草稿、字段级编辑与分享、搜索直达联系人；不增加新流程 |
| 无障碍与适配 | 自有控件键盘可达、焦点可见、标签明确；目标符合 WCAG AA；触摸目标至少 44px | 320/390/1024/1440 布局检查，无横向溢出；键盘及表单错误检查。截图检查不等同完整无障碍认证 |
| 功能完整性 | 微信输入、复制粘贴、拖拽文件、图片、聊天、文章、窗口操作保持可用 | 独立记录真实微信操作结果；系统对话框、剪贴板回传、中文与 emoji 必须验证 |
| 反馈与恢复 | 本地操作即时反馈；长任务显示阶段，可取消；失败留草稿，可重试 | 控件反馈目标 100ms；取消不继续占用扫描；网络断开后能重连，不重复发送 |
| 运行性能 | 集成层不因联系人或扫描范围增长而产生无界分配；交互不被后台工作阻塞 | 联系人按需展示，避免数千 DOM；扫描常驻页、有限缓冲区；以 PSS、私有内存、延迟和压力衡量 |
| 画面流畅性 | 自适应可读画质与链路；操作清晰、输入准确；连续使用不堆积延迟 | 在局域网测画面更新、输入与滚动；压缩、损伤检测、编码方案须比较后采用，不随意丢弃协议数据 |
| 系统稳定性 | 切账号不串数据；人工输入优先；后台任务互斥且能退出 | 身份守卫、取消、进程退出、连续开关页面、扫描重复运行、重连测试 |
| 包体积与复用 | 同内容跨架构仅存一份；只携带确有依赖的组件；安装不依赖临时网络 | 依赖闭包审计、离线包完整性、两架构校验；不能靠删输入法、字体、许可证或功能缩包 |
| AI 回复质量 | 针对完整消息轮次回答；主客体、引用、日期、本人信息准确；未知不编造承诺 | 测试本人风格、人工接管、身份开关、群聊分享边界、连续消息及图片。自然表达不能保证所有人无法识别自动回复 |
| AI 成本 | 同信息不重复发送；只带当前任务需要的记忆；输出长度与实际聊天一致 | 记录请求字符与服务返回 token；保持归属、隐私及发送安全规则。缓存或截断不得损害回答准确性 |
| 隐私与维护 | 密钥不落日志；账号隔离；升级保留数据；结果可追溯、可回退 | 准备升级前备份；保留来源、版本、包和安装后哈希；Git 远端验证与设备验收分别记录 |

## 基线

- 真机：192.168.3.7，x86_64，4 CPU，16GB；当前版本 0.10.20-stable.003。
- 全功能通用安装包：570,674,460 字节；主要体积来自双架构 Linux 兼容运行库，官方微信不在安装包内。
- 12.5 秒空闲采样：栖盒相关进程合计 PSS 约 1,638MiB，其中多数来自官方微信及其子进程；Node 约 114MiB。此数据不能当作密钥扫描峰值。
- 自动化基线：970 项 Node 测试全部通过。
- 我的信息：17 个可选字段、逐项分享、建议确认及历史恢复已有实现；本轮保留这些语义。
- 联系人：当前 Bot 账号 1,604 联系人、333 群；当前列表全量创建行。

## 多轮比较与完成条件

1. 第一轮：修复扫描冷页读取和前端大列表、改善个人信息编辑与保存；使用合成数据及真机读操作比较。
2. 第二轮：去掉 AI 上下文重复信息，依赖闭包和跨架构包复用优化；比较回复正确性、请求大小及安装包差异。
3. 第三轮：实际安装、微信与 AI 全流程检查、连续交互与资源采样；针对失败再修复并重验。

每轮记录采用与放弃的方案及原因。最终交付必须分别列出：源码测试、包完整性、fnOS 应用中心安装、真实微信/AI 操作、ARM64 验证边界、远端 Git 状态。没有真实 ARM64 设备就不能声称 ARM 真机通过。

## 已完成的比较（安装验收另记）

- 第一轮：真实 Bot 数据预览，联系人列表从 1,604 行减到首屏 18 行，末尾仍可通过键盘到达；搜索在完整数据上运行。手机 390px 页面无横向溢出，保存入口可见。预览仍使用 0.10.20 真机后端，不作为新包安装证明。
- 第二轮：NAS 上用 100,000 条合成消息比较旧、新 worker。旧代码空闲 RSS 为 79,495,168 字节且仍持有上次结果；新代码为 21,790,720 字节且结果已释放，约降低 72.6%。处理峰值两者均约 121MiB，不能据此声称峰值也降低。该项是硬件上的合成负载，并非真实用户聊天导出。
- 真正的输入阻塞：只读扫描和数据库队列退出人工输入等待链；会修改微信窗口、发送及清理草稿的队列继续保持互锁。专项回归覆盖只读请求未完成时输入可继续，以及未清理草稿的 Enter 仍被阻止。
- 冷会话扫描：当前测试进程已使用过，常驻页遍历只减少约 2.5% 读取量，冷定位仍约 4 秒；此样本没有显示内存峰值收益，不夸大效果。保留跳过未分配页机制，并对新版本动态发现的布局增加受进程、账号、可执行文件、时间和实时结构校验约束的私有提示复用；不能以提示替代发言身份校验。
- AI：完整原文只发一份，重复摘要和来信索引改为引用，风格不同时重复在系统正文和输入中。只改发送格式，本地归属校验保留完整原文；新增请求字符和实际接口 token 的无内容诊断计数。实际回复质量与 token 结果等待安装后检查。
- 缩包试验：静态 ELF 依赖表发现 `fcitx5-pinyin -> QtWebEngineWidgets`、`libavfilter8 -> libflite1`；因此保留这些输入法和媒体依赖。保留原始载荷哈希、许可证与双架构共享复用；额外交付适配此 x86_64 NAS 的单架构包，移除服务器未用的浏览器 PDF 构建和 JS 调试映射，并比较压缩等级。
- 发布前源码回归：976 项 Node 和 299 项 Python 单元测试通过；这些不是物理手机、屏幕阅读器或 ARM64 真机验收。
