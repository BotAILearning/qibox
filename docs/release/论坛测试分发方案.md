# 栖盒飞牛版：论坛测试与文件分享方案

核实日期：2026-09-10。当前安装包：0.1.10。本文是准备方案，不代表已开放分享或已发布论坛帖子。

## 推荐安排

采用“一个论坛主帖 + 一个独立发行目录 + 按版本保留材料”的方式管理测试。当前先发招募帖；飞牛确认可采用的测试分发方式、第三方组件源码提供事项完成后，再向确认的测试范围开放安装包。

首批建议邀请约 10–20 位愿意反馈的 x86_64 用户；ARM64 作为单独的兼容性测试，不把统一包有 ARM 组件写成 ARM 实机已全面验证。这个人数是便于维护反馈的建议，不是官方规则，也不是对分发规定的例外。

## 先处理两个已经查明的事项

1. **飞牛的分发指引。** [官方“测试应用”文档](https://developer.fnnas.com/docs/quick-started/test-application/)目前明确写着：“手动安装仅用于本地测试，不应作为公开分发方式。”因此不建议直接以公开论坛外链代替应用上架。先向飞牛社区主理人或应用中心开发者先锋交流群说明产品与测试范围，确认未上架测试包允许采用的渠道。不能自行假定加密码、私发或标注“内测”就自动符合这项指引。
2. **第三方组件对应源码。** 项目 `NOTICE.md` 已明确记录：公开分发前，GPL/LGPL 组件对应源码、修改说明及许可证事项尚需核验和补齐。应按实际组件及许可证准备对应版本源码、必要修改和构建说明、许可文件，并提供有效获取方式；不能只写一句“源码来自 Debian”或只附版权文件就称已完成。参见 [GNU 官方 FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#UnchangedJustBinary)。这项工作不等于要求把栖盒所有自有代码统一改成 GPL；自有代码与各组件的许可范围需要分别核对。

可发给社区工作人员的说明（仅草稿，未发送）：

> 你好，我是栖盒的开发者 Bot。栖盒是在飞牛 NAS 上运行官方 Linux 微信的第三方应用，目前已有 0.1.10 FPK，开发者申请还在进行，想先招募少量用户做兼容性和数据恢复测试。我看到开发文档说明手动安装用于本地测试、不应作为公开分发方式，想确认未上架应用是否有认可的小范围测试渠道；是否可以在论坛发招募帖，以及测试包应通过什么方式提供。可以按要求补交应用说明、截图和测试材料。

[官方“上架应用”文档](https://developer.fnnas.com/docs/quick-started/publish-application/)提供了通过飞牛粉丝群联系社区主理人、加入应用中心开发者先锋交流群提交材料的路径；开发者后台上线后的流程以平台实际指引为准。

## 文件怎么放

新建独立的发行文件夹，例如：

```text
栖盒测试发布/
  使用说明.txt
  0.1.10/
    qibox-0.1.10-all.fpk
    qibox-0.1.10-all.fpk.sha256
    安装说明.txt
    更新日志.txt
    已知问题.txt
    第三方组件说明.md
    licenses/
    sources/
```

这里只是目标结构，`sources/` 等发行材料还没有在本任务中补齐或对外提供。当前真实 FPK 与校验文件在项目 `dist` 目录。不要把整个项目目录、`.dev-data`、`.cache`、NAS 应用数据目录、实机诊断报告或历史聊天记录放入发行分享目录。

- 每次发布新版本增加一个新子目录，不用同一个文件名悄悄替换不同内容的 FPK。
- 顶层使用说明指向当前推荐测试版本，论坛主帖同步更新版本和日期。
- 保留前一版供定位差异；不能由“有旧包”推出支持无损降级，降级前需单独确认数据兼容。
- 微信安装包不随栖盒一起分享，继续由用户在栖盒内从腾讯官方来源下载。

本次已验证的 FPK：

```text
文件：qibox-0.1.10-all.fpk
大小：594850321 字节，约 567.3 MiB
SHA-256：dd28f0059365254c78233ddaa7251004d6b2db40c00269ab005ff025a2879bb0
```

若后续修改 FPK 内容，应递增产品版本、重新打包和校验，不能沿用上述校验值。

## 分享链接怎么做

局域网共享文件夹适合你自己整理文件；论坛网友需要的是能够在外网访问的文件下载链接。不要把 `192.168.3.7` 当成公网下载地址。

在获准的测试范围内，优先使用飞牛文件管理的外链分享，指向专门的发行文件或目录；如果当前版本只支持对文件生成外链，分别分享 FPK 和配套材料。建议初期用 14 天有效期、单独提取码，不限制到很小的访问次数，以免浏览和重试耗尽次数。提取码只是访问门槛，不是身份校验，也不替代分发许可。

飞牛官方帮助说明：开启 FN Connect 后可生成其文件分享链接；没有远程访问能力时，默认可能生成局域网 IPv4 地址。支持设置有效期、密码和访问次数，外链速度限制可在相应分享设置中检查。参见 [创建文件外部分享链接](https://help.fnnas.com/articles/v1/file/create-share-link)。

具体开放下载之前，使用手机移动数据或另一条外网，实际下载完整 FPK 并验证 SHA-256，确认访问者看到的范围、链接有效期、依赖说明和下载速度。这个外网下载测试与“手机微信向 NAS 迁移聊天记录”是两条不同的数据通路。

FPK 约 567 MiB，若外链实测速率仅 1 MB/s，单次下载大约需要 10 分钟。首批人数少时 NAS 外链便于管理；若人数增多或外网上行不够，再增加你可维护的网盘镜像，并保持文件名、版本和校验值一致。没有必要在第一轮就自建下载站、自动更新系统或公开 NAS 管理入口。

## 安装说明必须说清楚

- 当前为第三方测试版，尚未上架飞牛应用中心。
- 当前包声明最低 fnOS 版本为 1.2.0401，需对应架构的 Node.js 22。最低版本来自包配置，不表示该版本及以上所有系统均已实机验证。
- 通过飞牛认可的测试安装方式安装 FPK；若可用手动安装入口，优先写应用中心的界面步骤，不把 SSH 命令作为普通测试者默认流程。
- 栖盒安装完成后，从栖盒内另行安装官方微信，再添加实例并使用官方登录流程。
- 微信界面操作需要电脑浏览器；手机端目前仅提供安装相关入口。
- 程序运行不等于微信已登录或备份完成；手机全部历史记录不会自动导入。
- 持续备份会占用同一账号的电脑端登录，与电脑微信登录存在冲突，可能导致其中一端退出登录；适合主要使用手机、不需要同时使用电脑微信，或使用独立账号长期在线的场景。
- 闲时备份适合在夜间等不使用电脑微信的时段运行。使用一段时间后，若手机微信出现允许该设备自动登录的提示，完成授权且栖盒检测到自动登录已启用后才开放；不承诺固定天数或所有账号都会获得资格。闲时运行也存在同一账号的电脑端登录冲突，不能宣传为两端同时在线。
- 更新应用时避开聊天迁移和其他正在进行的传输。当前未完成全面覆盖升级与真实聊天恢复验收，不承诺任意版本直接升级或降级均无损。

## 论坛帖怎么安排

选择论坛当前的“应用分享”分类，标题标明“内测招募”和产品名。正文先说明解决什么需求，再写当前功能、适合参与的人、已知限制和反馈方式。使用同一个主帖维护版本，避免每个小版本都重新发帖。

配图建议两张：市场与多实例桌面、实际微信窗口。使用真实界面并处理账号、二维码和聊天内容。当前自动化测试生成的假运行器截图不能冒充实机成功截图。

[论坛发帖指南](https://club.fnnas.com/forum.php?mod=viewthread&tid=3021)说明可以使用高级模式的纯文本粘贴，图片应上传后插入。该指南列出的附件类型未包含 FPK，不应依赖直接把大型 FPK 附在帖子中。

配套帖子草稿见 `飞牛论坛发帖文案.md`，包含现在可用的招募版和获准分发后可替换的下载段落。
