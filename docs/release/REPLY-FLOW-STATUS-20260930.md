# 自动回复当前状态显示规则（2026-09-30）

## 需求与判定

- 联系人当前没有待处理来信，也没有正在执行的自动回复时，状态显示“空闲”和“当前没有正在执行的自动回复”；不展示流程条。
- 收到新来信并进入合并等待时，才展示当前轮次的流程和有效倒计时。汇总、请求模型、发送中的阶段只反映正在运行的自动回复。
- 模型决定跳过、发送完成、取消后，当前流程结束。完成结果保留在相应记录中，不在“实时状态”或联系人当前状态中继续显示。未回复记录保留来信、来源、时间和原因。
- 来信仍待处理且发送失败、等待重试时，继续展示失败原因与重试倒计时，不将失败误写成已完成。
- 主动聊天队列、主动聊天模型请求和追问等待不冒充一轮由新来信触发的自动回复流程。
- 点击“跳过倒计时”后按钮立即显示处理状态并防止重复提交；不等待整份 AI 状态和联系人列表重画。服务端只返回简短确认，并优先读取该联系人进入回复流程。操作失败时在按钮旁显示普通说明，不弹出红色全局提示。

## 原因

0.9.70 的服务端把最近 10 分钟内的 `skipped`、`sent` 等终态加入实时列表；联系人页在没有实时任务时还回退读取保存的 `replyFlow`。因此一条已经结束的回复轮次，会在没有待处理来信时显示“本轮不回复 / 本轮未发送”。

## 验证边界

- NAS `192.168.3.7` 只读状态在修复前确实返回了两条 `skipped` 和一条 `sent` 终态作为实时项，与用户截图一致。没有读取聊天正文，也没有触发发送。
- 本地检查覆盖空来信、等待、模型跳过、发送完成、发送失败重试；全量 Node 用例、代码检查和 1440px 浏览器交互回归通过。
- 跳过等待专项覆盖联系人和群聊、绕开全量会话扫描的优先处理，以及人为延迟服务端保存时按钮立即变为不可重复点击且没有红色提示。
- 此文件记录的是源码修复及本地验证。NAS 当前安装版仍需升级后核验设备页面与运行状态，才能称为真机修复完成。
