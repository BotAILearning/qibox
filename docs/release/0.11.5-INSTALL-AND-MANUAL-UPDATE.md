# 0.11.5 安装入口与手动更新

安装页以 c228520e 的原卡片布局为参考，定向移除复杂准备面板；保留其后设置重组、微信能力检测、窗口恢复和运行资源裁剪修复。环境准备、资源完整性校验、自检与错误后重试由后台安装链完成。

## 安装可靠性

生命周期回调只使用 manifest 声明的飞牛 Node.js 22，先验证依赖可执行，再执行资源恢复。阶段与具体失败输出写入 fnOS 的 `TRIM_TEMP_LOGFILE`，保留真实退出码；日志写入失败也不能伪装安装成功。依据：[fnOS 环境变量](https://developer.fnnas.com/docs/core-concepts/environment-variables/)。

app-assets 先校验整包 SHA-256，一次归档清单同时验证条目与类型，再解压至私有临时目录；完成后核对所有文件的大小、SHA-256 和权限。原有目录在发布失败时恢复；进程中断后可重入，锁校验 PID 与 Linux 启动标识，避免 PID 复用永久阻塞。不再以固定 180 秒杀死正常慢任务。微信 deb 解包同样保留子进程退出信号与具体错误，不以固定 180 秒推断失败。

N150 用户的原始现场日志和真机均不可得，不能把重复扫描、180 秒限制或某项资源不足认定为该报告的已确认根因。隔离 Linux 故障测试与主测试机结果分开记录；不将模拟测试写成 N150 真机通过。

## 微信手动更新

- 原微信卡片显示当前版本。只有用户主动点击“手动更新”后才向官方 HTTPS 安装包地址请求大小与整包校验元数据；后台轮询、应用启动和服务重启均不检查新版。
- 管理员确认共享程序影响的全部实例后，才下载官方安装包或导入官方 deb。下载按实际字节显示，支持暂停；重启保留断点，继续前重新展示影响并确认。
- 官方 HTTPS 对象元数据中的 MD5 用于整包传输校验，另计算本地 SHA-256 作为程序内容标识。MD5 不被描述为发行者签名；缺少可验证元数据时停止官方下载，允许用户导入官方 deb。导入同样校验 deb 结构、架构、ELF、路径与链接，版本号不作为白名单。
- 新程序先用全新隔离资料启动验证，通过后才停止实例、持久化手动恢复标记，最后原子切换 current。账号目录、聊天记录、配置与密钥不在程序替换范围。
- 更新后原实例保留并等待手动打开，原启动策略和 AI 开关不被关闭或重写。恢复标记在服务重启前加载；打开一个实例只解除该实例标记。
- 旧程序保留。验证或切换前失败可重试；新程序可能改变数据格式，因此不在启动后自动回退旧程序，直接降级被拒绝，需与旧程序匹配的完整数据备份。
- 通讯录与历史查询沿用独立能力检测；正常读取不因陌生版本号警告或阻断，权限、登录、占用等错误不冒充空数据。

## 验证边界

完整 FPK 继续包含 x86_64、ARM64 离线运行资源，体积门槛为 491,603,782 字节。最低系统 1.2.0401 与 ARM 仅做本地静态校验。最终包的实际字节、SHA-256、安装与升级结果、页面截图及未验证项随本次本地交付报告提供；不公开发布。
