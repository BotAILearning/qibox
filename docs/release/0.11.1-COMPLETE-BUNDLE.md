# 栖盒 0.11.1 完整运行组件随包说明

候选版本：`0.11.1-candidate.002`（`platform=all`）。本文件记录完整包的交付边界与本地准备流程，不代替本轮源码、FPK、NAS 或微信实测报告。

## FPK 交付边界

栖盒 FPK 随包提供支持架构的完整运行组件，包括共同资源、对应架构资源及私有回退资源。构建产物包含按架构选择的运行清单、内容哈希和离线资源；正常准备不需要从外部组件源下载运行库。FPK 不包含官方微信安装包。

安装时，栖盒读取本机架构并选择对应清单，在本地校验资源哈希与大小后展开运行环境并执行环境自检。只有与清单哈希匹配且符合复用策略的系统文件可被复用；未复用的组件仍从随包私有资源恢复。复用后的自检失败时，流程会改用完整私有后备；新环境通过文件校验和自检后才切换，失败时保留原环境。此处描述的是实现约束，不是本候选已通过设备验收的结论。

栖盒可复用 NAS 已有的合格组件以减少展开后的本地磁盘占用。完整组件及回退仍随 FPK 交付，因此系统复用不能记为商店下载量或 FPK 体积减少。`104/143` 这组数字不是 FPK 大小、包内组件比例或下载比例；应保留其原始本地统计口径，不据此推导删包或下载节省。

官方微信保持独立流程：用户首次使用时从微信官方来源下载安装，或导入与设备匹配的官方安装包。该流程不由栖盒运行组件离线资源代替，也不把微信客户端放进 FPK。

## 运行组件与资源来源

共同层和架构层由锁定的 Debian 组件来源构建，并由来源锁、内容清单和归档哈希对应。`payloadFormat: 3` 的归档分层及来源约束见 [运行时载荷格式](../RUNTIME-PAYLOAD-FORMAT.md)。补充运行库独立锁定 Debian Bookworm 版本、架构、下载地址及哈希；构建时验证官方索引信息和包内容，并作为本地随包补充资源交付。

运行环境准备期间校验随包资源、恢复私有文件与链接，再进行架构、动态依赖和 Python、FFmpeg 等组件自检。系统复用只影响已安装运行树的来源选择；私有后备继续保留在包内。运行环境、离线资源与微信程序的边界需要分别记录，不能把“无需下载运行组件”写成“无需获取官方微信”。

## QIAPP UI 组件版本

本轮设置界面使用 QIAPP 规范修订 `2026-10-18` 和从本地组件库接入的设置组合 CSS `0.1.2`。该组合 CSS 已随栖盒源码 vendor，不需要 Git 操作或运行时访问组件库工作区。底层已有 `@qiapp/ui` 资产仍为 `0.1.0`；本轮没有把底层运行组件版本写成 `0.1.2`，也不声称旧底层组件已经具备新规范中的所有能力。来源分别记录在 [`SETTINGS-SOURCE.md`](../../web/vendor/qiapp-ui/SETTINGS-SOURCE.md) 和 [`SOURCE.md`](../../web/vendor/qiapp-ui/SOURCE.md)。

## 完整离线恢复

1. 保留完整通用 FPK、校验清单，以及用户自己取得的对应架构官方微信 deb。`.qir` 是可选修复副本，正常 FPK 已含全部运行资源。
2. 安装完整 FPK 后在“准备微信”进行本机校验、自检；资源损坏时可重新安装同版完整 FPK，或导入本版本 `.qir` 再重试。不要用其他版本/架构的修复包。
3. 如 NAS 没有微信安装或可信缓存，离线导入自己的官方 deb。保留既有微信时直接复用，不覆盖其账号、聊天数据或配置。
4. 资料恢复使用既有数据备份与恢复入口。运行组件准备不承担账号资料备份；已有旧环境及升级备份继续保留，失败记录不清除。
