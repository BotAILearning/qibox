# 0.10.9–0.10.10 AI 送达回执跟进

0.10.8 恢复日常自动回复后，既有群聊的若干发送显示“发送结果无法确认”。只读核对实际微信数据库，确认发送基线后的唯一同内容本人消息已经存在；没有打开该群或向该群测试发送。

原因是微信有时先清空输入框，随后才发布数据库中的发送消息。旧逻辑最多读取五次，数据读取已预热时约一秒即耗尽。后续扫描能够核实消息，但没有同步更新发送状态和异常显示；重启还会按旧意图 ID 补入一条重复记录。

修复把核验改为最多八秒内的只读轮询，仍只提交一次发送。发送记录保留操作标识，延迟回执同步更新送达状态；重启只在已有可信回执唯一匹配时合并旧意图，不重复计数。旧格式还必须满足相同基线、有限时间窗口和完全相同内容，多条相同候选保留未确认。历史异常原文保留，核实后标注“已确认送达”，其他异常保持原状态。多段回复只确认实际送出的部分。

启动恢复先按操作标识和基线建立索引，避免对每条未知意图遍历全部历史；不重新提交消息、不改变回复次数上限、不删除用户记录。

旧版已由唯一真实回执核实、但操作标识丢失的记录，只在有效微信 ID 属于本程序已核实消息、有合法基线、附近历史异常唯一且没有相关未确认意图时补记“已确认送达”。无法满足这些条件的旧异常不推测结清。

自动化覆盖延迟超过五次读取、读取中断、身份或会话变化、重复意图恢复、已成功新回复后的旧意图恢复、歧义候选及部分发送。最终合并版 Node 全量 879 项、Python 全量 275 项及静态检查通过。

## 0.10.10 状态修正

0.10.9 的日常群后续出现一条暂未确认、随后由真实回执确认的发送。没有证据证明打开 AI 页面导致读取取消：AI 面板与微信屏幕是同级元素，事件监听不覆盖面板。已确认的问题是服务直接把 uncertain 结果写成 failed 和异常，而未知结果不能证明失败。

0.10.10 已将未知结果显示为“核实发送结果”，保留未知消息和 uncertain 审计，不重新发送、不提前计数；核实后同步次数与送达状态，并修正过时提示。明确未发送的失败仍显示失败、记录异常并允许按原机制重试。待核验记录保留群触发来源、原来信 ID、接收成员和任务关联；旧异常不删除。此改动不推测未核实结果为成功，也不以清空历史制造无异常。自动化验证未知结果只提交一次、不生成误报失败、不重复计数，以及明确失败仍记录异常。
