# 0.10.44 实时状态与图片、语音处理修复

基于远端 main `04727f9e1ec8e103030742deeca431640ed55757` 和真机已安装的 0.10.43。原工作区存在其他任务修改，本次在独立工作区开发、打包，不混入这些修改。

## 行为与原因

- 实时状态只显示仍在等待、生成、发送或核验的流程。核验已结束的 `unconfirmed` 和已发送、略过、取消等结果退出实时状态，保留历史证据。关闭 AI、暂停对象、达到回复上限、手动回复后不再接续的等待不再显示为运行中。
- 图片索引：微信消息 XML 中的 md5 不一定是本地附件文件名。按当前账号、聊天标识、消息本地 ID、时间和类型认证 `message_resource.db` 中的附件关联，再按文件大小核对缓存。优先原图，无法解码或未缓存时使用同一条消息的缩略图，明确提示模型不要猜测模糊细节。
- 请求实际携带图片：OpenAI 兼容接口使用 `image_url` 的 data URL，Anthropic 使用 base64 image block，绑定对应消息 ID。模型拒绝图片输入时略过图片；只有图片的本轮不再强制重试文字说明。图文混合沿用既有文字回退，移除图片及其全部本轮引用，只处理可读文字。本次不增加模型审核或自动重试次数。
- 语音继续调用微信本地“转文字”，不上传音频给外部识别服务。相邻图片、视频使用单独的媒体行校验，不再要求媒体具有文字气泡颜色；仍须验证账号、聊天、方向、媒体类型、唯一文字锚点及同一条语音控件。转写流程的本地操作时间预算从 28 秒调整为 90 秒，覆盖导航和微信转换等待，不改变模型请求次数。
- 图片读取失败、微信转写失败均从本轮模型上下文中略过；本轮全为失败媒体时直接结束，不调用模型、不发解释、不请求对方重发或转文字，私聊、群聊及 @我一致。保留原始聊天和历史记录，取消或配置变化时不冒认消息已处理。

## 验证

- Node 全套 1157 项通过，Python 320 项通过；语法、应用标识、版本与差异检查通过。覆盖已结束流程退出、失败媒体不回复、取消后不消费来信、真实图片请求块和不支持图片时的图文回退。
- 真机图片：修复前 6/6 读取失败，修复后及正式安装后 6/6 成功；其中 5 张只能取得可解码的微信缩略图，1 张取得完整 JPEG。文件按同一消息的本地索引认证，不按最新文件或时间猜测。
- 当前保存的 `glm-5.3-flash` 实际请求带 1 个图片块、220403 字节 JPEG，单次请求约 2681 毫秒返回有效 JSON，描述与图像的可见内容一致。当前模型图像输入依据[智谱官方文档](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-5.3-flash)。结果用于诊断，未向原聊天发送。
- 历史语音样本复现了相邻图片导致渲染校验中断的问题；修复后不再卡在该图片行，但历史语音不在当前可唯一匹配的可见窗口内，仍按规则略过。近期快照没有可用于完整转写验收的新语音，不能声称新语音的微信本地转换已在真机通过。
- 0.10.43 安装后的近期原生控件失败，私聊及群聊的准备、提交前取消在多次检查中通过；未输入或提交诊断正文。正式安装后出现一例群聊不可执行，随后该群从当前有效联系人中消失。按原账号、原群的唯一标识读取微信本地状态及系统记录，确认账号在此次复查期间已不在该群中；刷新联系人后移除待处理流程，保留配置与历史。未绕过微信的群成员状态继续发送。其他间歇性历史控件异常没有稳定复现，不能声称全部旧异常触发条件已解决。
- 当前 AI 界面浏览器回归通过，覆盖等待与跳过、模型设置、分析队列、报告历史、联系人搜索和文件交接，桌面及 390px 布局无脚本错误。这些是隔离夹具检查，不代表真实微信消息发送验收。
