# 0.10.43 最近异常修复

本次基于真机已安装的 0.10.42，处理最近两天的模型超时、微信数据写入期间读取失败，以及多日停留在“核实发送结果”的记录。历史异常保留，不能把历史余额、认证或旧格式错误当作当前仍在发生的问题。

## 原因与修复

- 发出后回执未确认的记录原先依赖会话索引变化才重读；索引不变时没有后续结论。增加独立的只读回执核验，即使关闭 AI 发送也继续检查。核验限定在原账号、原对象、原操作及发送时间范围内，唯一匹配才确认送达。三分钟仍不能确认时明确显示“核验已结束”，保留不确定证据，不自动重发、不虚增次数；后续取得真实回执仍可纠正结果。
- 最近大量模型超时发生在额外角色审核请求。按当前协作规则，将角色、事实归属、时间和本轮来信检查放在同一次生成请求里，只返回最终业务结果；保留本地账号、作者、身份披露、输出结构与发送校验，既有失败重试次数不扩大。官方 GLM 5.3 对聊天使用其支持的 low 推理强度，保留 thinking；自定义服务与其他任务配置不变。超时单独标为 `ai_model_timeout`，不再混同连接失败。
- 微信写入期间产生临时数据库快照冲突。对同一账号和进程的只读操作最多短暂重试两次；永久错误、取消或账号绑定变化立即结束。发送操作不走此重试。
- 启动修复未知回执时逐条核对正文，不能拿同一操作已送达的另一段消息确认未核实的一段。

## 安装前验证

- Node 1146 项通过，Python 317 项通过，语法、版本、应用标识与差异检查通过。
- 当前 AI 浏览器回归通过，包括等待与跳过、模型设置、分析队列、报告历史、搜索和文件交接；浏览器测试不代表物理手机验收。
- fnOS x86_64 原始账号范围上的历史回执通过隔离副本验证：截图对应的多日记录得到明确未确认结论，已确认的一段和已有次数保留，没有重发。
- 真机最近报错私聊、群聊与受控会话的原生准备及提交前取消通过，未输入或提交测试正文；近期控件失败在此次检查中没有复现，因此不宣称已找到其全部历史触发条件。
- 真机当前报错群聊的完整模型输入约 53056 字符，官方已保存模型单次请求约 8840 毫秒返回有效业务结果，无额外审核请求；生成结果未发送到原群。
