## 版本与构建编号

- 产品版本统一取自 `config/product.json`；`package.json`、`package-lock.json` 顶层和根包版本必须一致。
- **版本号按 `A.B.C` 三段理解（用户于 2026-09-16 确认）：**
  - **尾数 C**：常规修复、优化和小范围改动默认只递增 C。
  - **第二段 B**：有较大变化时才递增 B；普通新增功能或每次打包不默认提升 B。
  - **第一段 A**：必须等用户明确通知才能更新；不得因不兼容变更或其他版本惯例自行提升 A。不兼容变更仍需单独说明升级与数据兼容要求。
  - 例如 `0.6.0` 的常规修复通常进入 `0.6.1`；只有较大变化才考虑提升 B，提升 A 必须有用户明确指令。这些示例不分配下一版本。
- 同一目标版本的开发构建使用独立编号，例如 `0.2.4-debug.001`、`0.2.4-debug.002`；候选构建使用 `0.2.4-rc.001`。这些是交付编号，包内版本字段须遵守目标 NAS 格式。
- 开发测试窗口产物必须明确标识 debug。现有构建脚本尚未实现独立 debug/rc 通道；本规则不表示该能力已经实现。首个新 debug 交付需要核对目录、文件名和可见版本标识。
