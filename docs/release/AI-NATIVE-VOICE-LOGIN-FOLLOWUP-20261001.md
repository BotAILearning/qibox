# AI 回复约束、发送归属、登录恢复与原生语音验收

交付版本：0.10.14。基于已合并、真机验收的 0.10.10，处理后续人工等待、第二个微信通讯录、原生语音，以及主动说明机器人身份和虚假任务执行的问题。原有功能与交互验收见 [AI 功能与回复可靠性验收](AI-RELIABILITY-ACCEPTANCE-20260930.md)。绿联实现继续停止并清除，本轮只交付飞牛包。

## 修复与原因

1. **主动说明机器人身份、虚假任务完成**：聊天正文曾沿用助手式表达，任务目标和对方的要求也可能被模型误当作执行依据。新增优先于风格、示例、记忆和聊天指令的约束，普通聊天不主动说明 AI、机器人、模型、后台及生成过程；身份追问遵循本轮用户设置，不伪造真人在场证明。当前聊天没有执行外部操作的工具，明确向模型声明这一点，禁止虚称已完成、正在操作或稍后自动代办。建议、草稿和代码不作为实际操作凭据。
2. **文字和语音同样受约束**：检查最终分段正文、拼接正文以及语音朗读全文。违规结果只追加一次纠正生成，仍不合格则保留可定位的拦截记录，不发送。主动聊天采用同一底线，群聊必须回复规则也不能绕过检查。语音合成入口再次检查朗读全文，违规内容不能进入合成请求。图片中的机器人题材不受文字身份规则误伤。
3. **AI 回复后误入人工等待**：延迟确认的主动聊天消息没有在人工消息分类前统一确认，旧等待也可能残留到后续已确认 AI 回复之后。现在先核实发送归属，再判断人工回复；仅有可认证的发送记录才能修复旧等待。真正人工回复、明确停止后的五分钟等待和账号隔离保留，无法对应发送证据的等待不批量清除。
4. **新登录后好友列表不可用**：过期的未登录观测被长期保留，后台预热失败可能被当作成功。改用有有效期的登录状态，以当前微信进程的已认证账号数据补充证据；新注销、重启和账号变化优先于旧读结果。先预热通讯录，失败三十秒后重试，可选消息密钥扫描不再阻塞已就绪的通讯录。
5. **合成音频作为文件发送**：每个实例使用独立语音输入，通过微信自身的录音和发送语音控件提交。录音输入与播放声音分离，持续校验账号、会话、窗口遮挡和本轮录音流；超过约五十五秒保留文字，不截断录音。发送结果不明时仅核验，不自动重发。首轮实测发现播放管道短轮询未继续写完 PCM，已改为完整传输并保留取消及目标检查。

普通“收到”“明白”和提供建议仍可发送；AI 合成语音的来源标签保留。历史失败、真实消息、发送去重及回复次数均保留，没有清除异常记录来制造无异常结果。

## 验证边界

升级后的首个测试请求仍观察到较长等待：0.10.13 首轮约 351 秒，其中模型请求约 2.5 秒、文字发送约 40 秒；0.10.14 首轮约 225 秒。已核对当前进程和数据缓存归属正常，尚未确认剩余启动汇总等待的完整原因，不能声称所有回复延迟均已解决。最终版后续正常请求约 75 秒收到文字、144 秒收到语音；语音后的普通文字回复约 92 秒。这些时间包含现有汇总等待及发送核验，未作为纯模型请求耗时。

语音使用普通合成接口，不克隆真人音色。本轮以收发双方实际微信消息类型和时长确认原生语音，未进行音色或逐字听辨认证。多位真实群成员同批点名仍沿用前一轮的自动化证据，未用额外真人账号验收。不承诺网络、模型及微信环境永久零异常。
