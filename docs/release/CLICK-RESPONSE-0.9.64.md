# 0.9.64 点击响应与群聊回复核验

## 原因

- 联系人、群聊 ID 已由微信只读数据接口保存，但“打开聊天”和自动发送的原生定位在目标不处于当前窗口时仍扫描微信的虚拟会话列表。列表只暴露当前视口，向上、向下滚动最坏耗尽 90 秒操作预算。
- “显示微信”原先只判断窗口可见。真机上微信子窗口取得焦点后，主窗口虽然可见，原生会话核验仍因焦点不属于目标进程而停止。
- 真机微信构建 `ce28c3471d532eeb1f136482eeb4d0bdfd59c06e` 的当前会话由两个独立对象保存，不再是旧版会话向量中的同一指针。旧校验将正确的目标群 ID 判为不可用。只读真机探针在两个位置均核对到目标 ID，且连续两次读取一致。
- 微信重启后未选中聊天时，旧会话读取报错被当成导航终止；现在把它判为“需要定位”。微信搜索框的辅助接口写字不会触发实际搜索；输入框焦点校验通过后发送一次空格和退格键，搜索结果立即出现。
- 搜索结果同时包含“搜索网络结果”的同名建议和“群聊”中的真实结果。旧匹配会点击前者，打开微信附带的网页搜索窗口。现在只取“群聊”或“联系人”分组下的行，随后核对私有会话 ID；全网搜索建议不会成为候选。
- 这些错误出现在发送键按下之前。运行记录必须标记“未发送、等待重试”，不能记成“已发送”或普通跳过。

## 点击路径审查

| 用户操作 | 原路径和等待来源 | 本版处理 |
| --- | --- | --- |
| 执行记录中“打开聊天” | 保存了 ID，点击时仍额外重取整份联系人数据，然后可能长距离滚动微信会话列表 | 使用已验证的绑定 ID；当前会话匹配时直接打开；否则在微信搜索中快速定位候选并核对真实 ID。点击后立即显示“正在打开聊天”。 |
| 自动回复选择群聊或联系人 | 后台发送可能逐页滚动会话列表；搜索建议混入同名候选 | 使用相同的快速搜索，只取对应分类，最终由只读会话 ID 核验；未确认身份时绝不发送。 |
| 微信窗口显示、聊天打开 | 已可见时不再激活主窗口；子窗口抢焦点使点击后报错 | 在需要操作微信时，按已知进程 ID 选唯一主窗口并激活，随后重新核实焦点。 |
| 联系人与聊天记录读取、日期范围 | 已通过私有只读数据接口，未使用页面翻页读取 | 保持接口读取；打开聊天不再为导航重复读取联系人快照。 |
| AI 回复等待、汇总、请求、发送 | 等待阶段可能被误认为卡住 | 页面按实际阶段展示剩余时间；真实等待可跳过；失败另记未发送并等待自动重试。 |
| 运行记录、最近异常、手机 AI 开关 | 记录按页取、详情按需取；手机开关由接口读写且有操作状态 | 保留按需接口；无整页 UI 扫描。 |
| NAS 文件选择与导出 | NAS 授权选择走宿主接口；微信文件保存完成前需等微信实际写完，页面有进度 | 保留真实完成确认及进度，不把固定轮询当作点击后的等待倒计时。 |
| 用户主动勾选语音、图片的聊天分析 | 媒体读取和模型处理提高分析准确性，已有进度 | 保留，默认关闭。 |

- 正式包：`0.9.64-debug.001` 经 fnOS 应用中心升级完成（任务 `1790699336485258515-qibox`，状态 2，进度 100%）；安装文件中的会话定位、发送与会话核验源码哈希与本地正式源码一致。应用服务与微信进程已恢复，用户数据校验值未变。
- 页面：真机桌面 1280 像素及手机 390 像素均显示“等待汇总 → 汇总上下文 → AI 请求中 → 发送中 → 已发送”，无页面脚本错误。完成态无“跳过等待”按钮；等待态按钮及跳过后立即推进由本地测试覆盖。本次未人为制造新的群消息，正式包安装后未重复发送同一条回复。
