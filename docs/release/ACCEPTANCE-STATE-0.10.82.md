# 0.10.82 验收状态

微信重启时，数据读取进程可能在异步账号检查期间退出。旧进程完成清理后，请求仍被挂入旧队列，导致联系人刷新、自动回复和应用停止一直等待。本版在异步检查返回后再次检查退出和取消状态，让失效请求结束并释放队列。针对性回归先复现永久等待，再验证修复后可以重新扫描和读取。

本版同时交付登录画面提示、飞牛 HTTP 200 失效会话识别和会话失效后旧页面清理修复。失效会话不能被误判为成功下载，迟到的请求不能重新填充已清空的私有界面。手机范围回归等待实际布局切换完成，再检查工作区关闭和轮询停止。

最终交付构建为 `0.10.82-stable.002`，`.001` 是未安装的内部候选。完整 Node 测试 1290 项、Python 测试 313 项及语法检查通过；当前 AI 工作区、手机范围、会话失效和迟到响应的隔离界面回归通过。旧比例脚本仍包含手机端打开完整分析工作区的过时假设，其失败记录保留，没有把它写为通过。

本次稳定包面向既有 fnOS 测试环境交付。冷启动历史慢样本、72 小时与 7 天真实观察、ARM/iOS 硬件、独立普通用户、兼容矩阵、离线恢复和完整回滚仍按原台账保留。会话专项的隔离回归不替代最终原生门户退出复验；不表示全量验收或官方审核已完成。

正式包安装后，485 个程序文件和 1130 个资源文件校验一致，3 个原模型及实际密钥、模型分配、设置与默认风格保留。三轮后台启动均无需扫码或手机确认，逐次完成真实联系人刷新和一对一测试往返；两端各确认三次发送/收件，无重复消息。一次发送进入待核实后由实际收件结果确认，未通过重发处理。

原默认模型在本轮返回 HTTP 429，第三个已配置模型返回接口或模型不存在；真实回复回归临时使用连接测试通过的既有备用模型，结束后恢复原分配。最后复测默认模型仍返回 429，此项服务可用性没有关闭。辅助发送端一次明确未发送且收件记录为空后，受控重试成功，原失败证据保留。

最后通过应用中心正常停止、启动服务，用时分别约 8.4 秒和 4.2 秒，随后自动恢复登录并再次完成联系人刷新。首次升级曾因旧版已卡住的读取队列无法停止而失败；在明确确认升级失败后结束旧的失效请求，再通过应用中心升级成功。最终包的正常停启未再出现该问题。在线备份可读，未以此代替离线恢复验证。
