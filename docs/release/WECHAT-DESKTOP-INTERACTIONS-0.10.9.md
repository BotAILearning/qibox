# 微信与当前设备交互：0.10.9 验收记录

本轮处理微信内容无法复制到当前设备的问题，并检查输入、复制粘贴、文件选择、拖入、保存和重新连接。体验目标是按用户要求，操作直接、结果清楚、失败后可继续；未完成对网易 UU 远程桌面客户端本身的实测，不将本轮结果表述为与其全部能力相同。

## 最终行为

- 在微信执行文字复制或剪切后，当前有焦点的栖盒页面接收内容并写入本机剪贴板。HTTP 连接可使用浏览器复制回退；权限失败时保留“复制到本机”和保存入口。中文、emoji 和多行文字保持完整，微信与 Windows 换行约定允许 LF/CRLF 转换。
- 在微信复制图片后，通过安全连接写入本机 PNG 剪贴板。HTTP 和浏览器权限限制时，明确提示并保留图片保存入口；普通文件和多个文件进入文件保存流程。
- 本机文字粘贴、中文提交、截图或文件粘贴、文件拖入，通过当前实例的私有环境处理。只有当前已经聚焦的聊天编辑器允许手动文件准备；主窗口和独立聊天窗口都支持。只准备草稿，发送仍由用户在微信确认。
- 微信原有“发送文件”按钮打开来源选择，可选本地或 NAS。关闭、取消和失败不会自动发送。中文文件名不再因为缺少 UTF-8 环境被微信静默忽略；私有中文 locale 保留中文界面，不修改 NAS 全局语言环境。
- 保存到当前设备时优先使用浏览器保存位置选择；不支持时交给浏览器下载，提示以下载列表为准。保存到 NAS 使用原有目录选择和权限检查。多文件不覆盖已有同名目标，失败只清理本次新建的未完成文件。
- 浏览器一次提交多行内容只粘贴一次；准备过程中保护焦点，失败保留文本并丢弃已排队的发送键。重连移除旧输入处理器，释放按键和鼠标状态；独立聊天窗口存在时保留当前微信窗口，避免重连返回错误。

## 未证明的能力

- 物理 Windows 中文输入法候选窗和所有第三方输入法；浏览器 CDP 中文合成检查仅验证网页事件处理。
- 原生 Windows 文件选择/保存对话框的每项操作；浏览器文件输入和下载流已单独验证。
- 飞牛宿主的 NAS 目录授权和实际目标文件写入；本次测试用户未授权目录。不能将隔离模块或模拟目录选择的成功当作此项真机通过。
- macOS、Linux 客户端、实体手机的剪贴板与拖放、Safari/Firefox 权限差异及 ARM64 NAS 硬件安装。
- 浏览器无法替任意客户端的操作系统提供通用文件剪贴板。普通文件明确选择保存目标；HTTP 图片复制受浏览器安全上下文限制。
