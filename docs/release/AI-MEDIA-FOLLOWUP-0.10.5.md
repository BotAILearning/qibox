# 0.10.5真实微信媒体发送修正

MiniMax真实图片请求已经返回了生成任务，生成后的图片粘贴进微信4.1输入框，以单个内嵌对象显示，没有独立弹窗。原逻辑只接受新建预览弹窗，造成图片留在草稿里；真实记录核对确认没有发出，测试自身的草稿已清理。

兼容图片在原来空输入框中产生单个内嵌对象的方式。连续观察后重新核验原窗口、标题、编辑器、账号对象及发送区域无遮挡，才点击一次发送。

音频的文件剪贴板粘贴在当前微信中没有产生预览，还触发了文件复制入口。改用微信“发送文件”按钮，并让本实例的文件选择器只接收这一份生成的 MP3。已有文件选择或导出会阻止准备；测试/取消/失败只清理所拥有的请求；文件名、账号对象及独立预览核验后才点击一次发送。发送回执仍由微信真实记录独立确认。

关闭文件选择后，Qt 会保留一个没有子控件、没有实际窗口的“选择文件”对象，曾被当成遮挡。增加实际窗口校验，保留对真实弹窗的阻断。修正媒体清理预算不符合控件层上限的问题，清理失败也保留原始固定错误原因，避免覆盖定位线索。

提交前失败只清理本次拥有的内嵌对象；其他文字草稿、切换聊天、弹窗遮挡及点击后未知结果都不会清空或重发。新增回归覆盖内嵌发送、对象变化、侧栏遮挡、生成文件选择、已有请求、取消清理和残留窗口。Node 全量 850 项、Python 全量 265 项及静态检查通过。最终真机图片及音频结果在完整验收记录中列出。
