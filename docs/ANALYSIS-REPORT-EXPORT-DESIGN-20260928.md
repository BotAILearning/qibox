# 分析报告导出与批量导出设计

状态：已完成本地实现及自动化验证；fnOS 真机安装与下载验收待执行。已纳入 `docs/PRODUCT-SPEC-BASELINE-20260927.md` 1.7。

## 目标与范围

- 电脑端可将一份已成功保存的「分析报告」导出为 Word（`.docx`）或 PDF（`.pdf`）。
- 可从本次成功报告或历史列表批量导出；每份历史快照生成一个独立文件，批量结果下载为一个 `.zip`。
- 导出读取生成时保存的报告快照，不重新读取微信聊天、不重新调用模型、不修改报告或聊天记录。相同联系人在不同时间生成的报告视为不同快照。
- 与现有分析工作台范围一致：手机端不增加 AI 工作台或导出入口。

## 页面与操作

### 单份导出

1. 本次报告的成功卡片以及历史报告详情页，在「复制全文」旁增加「导出」。历史列表每行保留「查看」，并可直接使用行内「导出」。
2. 点击「导出」打开统一对话框：标题为「导出分析报告」，显示联系人、实际覆盖日期、生成时间；格式选项仅写「PDF（.pdf）」和「Word（.docx）」，默认选中 PDF。
3. 点击「下载」后生成并触发一次下载。按钮在处理中显示「正在准备文件…」且防止重复提交；成功时关闭对话框并提示文件已下载，浏览器拦截下载时给出可重试提示。
4. 仅 `complete` 且有 `historyId` 的本次报告可导出。等待、执行、失败、取消、空数据状态不显示导出。报告刚完成但历史刷新延迟时，可依据已返回的 `historyId` 读取快照。

### 批量导出

1. 本次报告区域在至少有一份成功报告时显示「批量导出本次报告」；只收集本次已成功保存的报告，旁边标明「可导出 N 份」。失败、取消、空数据对象不进入导出清单。
2. 历史报告标题右侧增加「批量导出」。点击后列表进入选择模式：每份快照前显示复选框，顶部提供「全选当前列表 / 取消全选」，底部固定操作栏显示「已选 N 份」「取消」「继续导出」。离开选择模式、切换实例或微信账号时清空选择。
3. 点击「继续导出」打开同一对话框，摘要区显示「已选 N 份报告」和「下载为 ZIP」，并注明 ZIP 内每份报告各占一个文件；一次选择一种格式，适用于这一批全部报告。未选择时按钮禁用。
4. 生成前按报告 ID 固定本批清单。报告在选择后被删除、账号发生变化或任何一份无法读取时，整批停止并列出原因，保留尚有效的勾选供用户调整；不能悄悄跳过失败项或把别的账号报告装入压缩包。
5. 处理时显示进度或当前阶段及「取消」。取消后停止生成并清理临时结果；下载开始后取消不撤回浏览器已经保存的文件。

### 导出弹窗布局

弹窗居中，宽度约 480px。标题和关闭入口位于顶部；紧接着用一行浅色摘要卡展示本次选择数量与 ZIP 下载结果。下方「文件格式」使用两张等宽可点击卡片，卡片内只放格式名称与扩展名，以选中边框和单选状态区分。底部左侧不重复说明格式，右侧放「取消」和高亮的「下载 ZIP」。单份报告沿用同一布局，将摘要改为联系人和日期，主按钮改为「下载文件」。

可预览的视觉稿：`design/ai-assistant/2026-09-28/analysis-report-export-dialog.html`。

```text
历史分析报告                              [批量导出]
□ 林宝平_Bot   2026-09-01 至 2026-09-20   [查看] [导出]
□ 林宝平_Bot   2026-08-01 至 2026-08-31   [查看] [导出]

已选 2 份                       [取消] [继续导出]

导出分析报告
已选 2 份报告                           下载为 ZIP

文件格式
[◉ PDF  .pdf]      [○ Word  .docx]

每份报告生成独立文件。                [取消] [下载 ZIP]
```

选择模式仅显示一次批量操作栏，避免每行重复出现格式选项。键盘可操作复选框、格式单选和取消按钮；对话框关闭、Esc 不启动导出。

## 文件内容与命名

每份 Word/PDF 使用相同的信息顺序和文字来源：

1. 标题「分析报告」、联系人显示名、生成时间（北京时间）。
2. 用户选择的时间范围和实际可读/分析覆盖范围分别列出；「全部」不能被误写成某个预设天数。
3. 当前快照已有的消息数、双方消息量、活跃天数等统计；对缺失指标不补造数值。
4. 跳过、截断、抽样或读取不足等覆盖提示，与页面表达保持一致，并在正文之前清楚展示。
5. 已保存的分析要求和报告正文。标题、段落、换行和中文标点保留；纯文本正文不得当作 HTML 执行。文件不附加原始聊天记录、附件或隐藏账号资料。

PDF 为可选择文字的文档，嵌入或随包提供可用的中文字体，避免 NAS 环境出现方框或乱码；Word 使用可编辑标题、段落、表格/统计块样式。两种格式均使用 A4 页面、合理页边距与自动分页，长联系人名、长章节和多页报告不裁切。

单份文件名建议为 `分析报告_联系人_生成时间_报告ID后8位.pdf`（Word 对应 `.docx`）；批量压缩包为 `分析报告_批量_导出时间_N份.zip`。文件名中的非法字符替换为安全字符，限制长度；同名快照依靠 ID 后缀区分。ZIP 内只放所选报告文件，条目使用安全相对路径，不写入绝对路径或 `..`。

## 实现契约建议

- 增加同源鉴权导出接口，输入为报告 ID 列表和 `pdf | docx`；一份返回对应文档，多份返回 ZIP。接口应复用现有实例、当前微信账号和报告 ID 检查，并在写出文件前再次验证账号未变化。
- 所有导出内容均从服务端的持久化快照读取；本次生成页面只传 `historyId`，不传可被客户端改写的正文。服务端一次解析固定清单，发现缺失或越权即拒绝整批。
- 下载响应使用正确 MIME、`Content-Disposition: attachment` 与 `Cache-Control: no-store`。生成过程不长期保存明文临时文件；临时文件在成功、失败和取消时均清理。不要把报告正文写入普通日志。
- DOCX 与 PDF 生成共用一份规范化的报告视图模型，使标题、范围、指标、覆盖提示和正文一致。生成库、中文字体和压缩能力需纳入 fnOS 包并验证实际体积与运行环境；不依赖 NAS 额外安装 Office/LibreOffice。
- 批量人数/文件总量不在设计阶段臆造固定上限。实现时应有资源预算、超限前明确提示和可取消的处理；正式上限以容量测试结果确定并写回产品规格。

## 验收清单

- 单份 Word、单份 PDF、同批多份 Word/PDF 均能下载并打开；内容、统计、日期与历史快照一致，正文无丢段、乱码、分页裁切。
- 同一联系人多次历史报告各有独立文件；本次部分成功只导出成功项；导出不调用模型或读取原始微信聊天。
- 账号/实例切换、越权 ID、已删除快照、生成中取消、下载失败、磁盘或内存不足有明确结果；失败不产生貌似完整的文件，不改变历史。
- ZIP 条目数量与选择数一致，解压后没有重名覆盖或不安全路径；大批量在实测容量内可完成且可取消。
- fnOS x86_64 真机安装后验证中文 PDF、Word 与 ZIP；本地生成成功不能代替安装后验收。其他架构及 UGOS 分别验收。
