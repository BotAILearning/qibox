## 1. 个人信息 Wiki

2026-09-25 用户补充：产品标题保持「聊天记忆」。基础字段是从当前聊天记录中提取的对方资料，不把用户本人、第三人、猜测或引述误作对方资料；空字段也以固定模板展示，每个字段可保留多个待判断的值。地址字段集中展示。「其他」存兴趣爱好与双方其他值得保留的聊天记录，旧版自由文本仍兼容归入该字段；其长文本框自动增高，右边缘与风格说明区域对齐。移除「添加信息」下方的说明文字。

- 将每位联系人记忆表示为带稳定 ID 的字段和值：姓名、手机号、生日（农历或公历）、其他重要日期、学校和对应学历、户籍地、居住地址、工作地点、工作单位、收货地址、其他。字段可有多个值；地址和工作信息的每个值带起止或记录时间，未知时间保持未知，不推断。
- 每个值独立显示为可编辑的泡泡，右上角可删除；支持添加、修改、保存、撤销或恢复。姓名值提供“添加为微信备注”操作；修改必须由后端接口直接完成，不通过微信页面控件。仅在已核实账号与联系人身份、用户明确点击时写入原生微信备注，并回读确认结果；没有可验证的写入接口时明确标为不可用，原 Wiki 值保留，不谎报成功。
- 旧版所有自由文本学习记忆无损进入“其他”，重复迁移不产生重复项。新学习发现同字段多个有依据的值时逐个存入；冲突值并列供用户修改或删除，不凭模型猜测覆盖。手动修改的值受保护，历史与加密存储继续有效。
- 更新学习、增量回复、候选记忆合并及模型输入协议；维持一位联系人一次读取、一次模型调用的现有边界和隐私规则。验证旧数据迁移、多值、日期类型、时间、删除、编辑、恢复与模型输出异常。

## 2. 运行记录

- 任务列表字段与筛选条件保持现有含义；重新排版自动回复、主动聊天和未回复区域。按钮大小、点击区域、行间距、窄屏折行及空/加载/错误状态要能正常操作，不出现重叠、横向裁切或误触。

## 3. 未回复定位

- 点击后先用已保存的账号、对象、消息 ID 打开正确聊天，再异步按消息附近时间和稳定 ID 精确定位；不要把整段历史读取作为打开聊天的前置条件。候选匹配须校验账号、对象、方向和消息，不能用昵称或模糊正文直接确认。
- 分别向用户报告“已打开并定位”“已打开但无法定位”“打开失败”。失败保留记录和可重试入口；取消或切换实例时旧请求不得操作新实例。针对旧消息、同文重复、数据接口失败和跨账号写回回归测试，并在真机记录打开耗时和定位结果。

## 4. 回复上限

- 联系人和群聊列表直接展示达到连续自动回复上限的状态、已用次数与上限。配置上限时提供“应用到全部联系人”和“应用到全部群聊”两个独立操作；只修改对应类型，保留每位对象的其他策略和手动暂停状态，明确保存结果与失败。

## 5. 开发部署与桌面连续性

- 查清开发写入、重启或版本切换使飞牛桌面图标消失的具体环节，采用不中断用户现有栖盒入口的开发/验证方案。代码推送、构建、本地测试不应触发真机现有应用关闭；需要切换服务时保留可回滚版本、缩短窗口、验证图标和入口自动恢复，不能让并行运行内容争用同一服务或数据。
- 真机验证必须覆盖安装态栖盒后台启动与 Bot 自动登录、现有入口、Wiki 增删改、运行记录布局、未回复定位、上限显示与批量应用；记录实际通过/失败和设备边界。桌面图标无需点击。微信备注接口写入按用户决定延期，不计入本轮验收。不得将本地模拟视为安装态真机验收。打包前版本号按 A.B.C 规则调整，并核对包内容；打包后仅提交本任务改动、同步 Git、核对远端提交。

本地和设备上的开发预览使用 `npm run dev:shadow`。该命令从当前源码目录启动独立 `--dev` 进程、随机 loopback 端口和临时数据目录；开发模式固定使用当前源码根目录，并且不会采用 fnOS 注入的生产 `TRIM_APPDEST` / `TRIM_PKGVAR`，也不会检查、删除或绑定生产 `app.sock`。结束预览时只关闭这个子进程并清理其临时数据。设备真机原生验收仍需在已有安装态入口可继续使用的前提下完成，预览模式本身不会启动或控制现有 WeChat 进程。
