# 微信本地数据接口（0.1.33）

0.1.30 实机修复：Linux 微信 4.1.13.9 的 SQLCipher 密钥缓存使用循环 XOR 编码。读取器先匹配加密参数结构，验证盐值、读写上下文及缓存指针；利用缓存末尾已知盐值恢复编码，并以第一页 HMAC-SHA512 认证候选密钥。兼容原有明文缓存，不硬编码微信可执行文件地址或某一版本的编码掩码。仅扫描当前实例进程的可读写私有区域，保持限时、只读和不持久化。

实机结论（BUG-020）：**每个数据库使用各自的密钥**，contact.db 的密钥无法解开任何消息分片，分片之间也不通用；微信只为它当前打开的数据库缓存密钥，未打开的分片的密钥在进程内存中并不存在。因此密钥发现只对缺失分片做一次带预算的搜索并记住“ searched but absent”，后续读取直接跳过，而不是每次请求都重扫整个地址空间。已发现的密钥以实例 `ai-secret.key` 派生的密文写入实例目录下的加密缓存，库文件不变即可跨微信重启复用。

联系人与历史消息默认通过 `DataChatBridge → wechat-data.py → wechat-sqlite.py` 读取。这是栖盒的本地适配层，没有连接第三方微信网关。联系人和历史读取不操作窗口，不调用通讯录分页、个人资料扫描或聊天页面读取。发送文字仍由原生桌面完成身份、草稿、消息版本与取消校验，不能称为接口发送；发送前后同时核对数据接口中的消息版本与新增回执。

0.1.32 的数据发送路径使用原生 `read-guard / send-guard`：只为防止发送期间界面内容或对象变化计算不透明指纹，不再通过气泡颜色判断发送人或解析历史供模型使用。原生提交返回 `submitted`，随后必须读到新提交的、身份唯一且正文匹配的本人数据库消息才确认成功。资料面板正常关闭使用本次操作的剩余时间；取消和过期后的应急清理仍限制在 1.5 秒内，不能放宽取消时的输入隔离。

通过当前实例微信 PID 已打开的联系人数据库定位当前账号，拒绝其他实例目录和多账号歧义。联系人一次查询，同名对象使用各自的内部身份。选择对象并学习后才将相应聊天交给已配置并同意使用的模型；每次最多 10 位，资料在内存按联系人整理后一次提交。微信账号内部 ID 和微信号不是同一字段，分别生成数据身份和原生发送校验身份。

本地适配针对 SQLCipher 4 的 4096 字节页、80 字节保留区。Node 父进程打开自己启动的微信子进程的只读内存描述符并传给私有助手，寻找经过数据库认证的密钥，然后按需解密页面。密钥不进入命令参数、日志、HTTP 响应或持久化文件。不注入或修改微信进程，不提升权限、不改变系统 ptrace 设置；系统拒绝读取时返回简短错误，不回退为通讯录界面扫描。助手退出后不保留密钥或明文页面。

只查询联系人和消息数据库。联系人表排除群成员条目、公众号、系统对象和当前用户，当前 AI 功能仍仅支持个人单聊。跨消息分片按真实消息身份合并，保留时间和本人/对方/系统方向；每个对象最多取最近 300 条并限制整体大小。解析 UTF-8、zstd 和常见 XML；图片、语音等媒体仅保留类型提示，不读取或上传附件。未知格式、未知发言人和冲突消息身份会中止本次读取。

SQLite 通过只读虚拟文件接口按需访问，解密页面缓存最多 256 页，不复制整库或写入明文数据库。WAL 只应用完整事务；存在共享索引时，以其中公布的提交边界为准。每次查询完成后及整批返回前核对数据库、WAL 与共享索引，发生变化则重试，避免把不同时间的分片混合返回。密钥扫描和查询有超时与大小限制，无法读取时不冒充返回空列表。

升级后通过精确的旧账号和联系人身份映射保留能够核实的策略与对象选择；账号发生变化时关闭总开关，不能靠昵称迁移配置。0.1.31 起，同一账号的刷新、策略修改和服务重启保留用户选择的总开关；启动时重新读取通讯录并校验账号后才继续自动回复。旧主动队列和延后追问不自动续发。发送回执需要新增的数据库消息身份，结果不确定时暂停该联系人且不重发。

数据接口的消息身份稳定，回复进度仅保存消息 ID、版本、最后观察时间及待回复标志，不保存正文。首次观察会处理策略生效后收到的消息；刷新和重启保留已观察及已处理位置，防止把新消息吞作基线或重放已处理消息。原生界面的临时消息账本仍只保留在内存，不能跨重启复用。

AI 入口首次需要确认登录且桌面已连接；确认后，短暂未知状态或状态请求失败保留入口、面板和表单。明确退出登录、停止微信、断开桌面或切换实例仍隐藏并清理。入口状态不作为执行权限；读取单独校验当前登录、进程与账号。登录检测跳过聊天内容及设置中的登录方式，避免完整聊天树引起超时，或把设置中的“扫码登录”误判为登录页。

实现参考：

- [SQLCipher 设计](https://www.zetetic.net/sqlcipher/design/)：加密页、认证与保留区。
- [SQLite WAL 格式](https://www.sqlite.org/walformat.html)：事务提交、共享索引和并发写入。
- [Linux WeChat Agent 的本地读取代码](https://github.com/xiaoguiwucan/linux-wechat-agent/tree/main/tools/wechat-decrypt)：Linux 微信的数据库位置、密钥缓存形式及消息/联系人字段。新实现独立编写，未运行或打包该项目。

联系人查询限于 local_type=1 的好友记录，并在存在 delete_flag 时排除已删除记录，避免系统条目和其他缓存对象出现在 AI 选择列表。

验证边界：0.1.30 已通过 SSH 在用户指定的飞牛 x86_64 设备、Linux 微信 4.1.13.9 上复现并修复读取失败；修复后接口连续三次读取成功，进一步排除两项系统条目后为 49 位好友，测试联系人的历史消息解析成功。此证据不代表 ARM64、其他微信版本和真实自动发送验收。本轮未发送微信消息；更多安装与验证结果见 [实机记录](../reports/CONTACTS-DATA-0.1.30.md)。

0.1.32 补充验证：相同设备上真实模型生成、原生发送及数据库回执已通过，用户确认“林宝平_Bot”收到自动回复。取消只读发送准备会保留待回复消息，不再误暂停联系人；提交后没有回执仍禁止自动重发。完整记录见 [自动回复实机验证](../reports/AI-REPLY-0.1.32.md)。
