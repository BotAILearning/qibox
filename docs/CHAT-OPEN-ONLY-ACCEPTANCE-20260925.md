# 聊天记录：只打开聊天（0.9.9-debug.002）

## 方案

- 记录列表仅保留“打开聊天”按钮。记录正文不再触发定位，也不提供定位状态、重试或定位接口。
- 点击时按当前栖盒实例、微信账号和联系人身份调用 `open-conversation`。后端从当前账号绑定的联系人资料取得原生身份，原生桥接在打开前后核验微信会话与聊天标题；不读取或滚动消息位置，不发送消息。
- 已确认可见的栖盒私有微信窗口复用最近的窗口状态，避免每次点击重复扫描 X 窗口。窗口未知或隐藏时仍执行恢复检查。
- 学习记忆、自动回复和聊天记录读取流程保持各自原有用途；“打开聊天”不依赖目标消息能否在微信视口内找到。

## 真机验收

- 设备：`192.168.3.7`，Bot 账号，唯一好友联系人“毒药💊”。测试通过后未改动联系人设置、未发送聊天消息。
- 应用中心升级任务返回 `status=2, progress=100`；安装版本为 `0.9.9`、构建号为 `0.9.9-debug.002`，服务状态为 `running`，原数据卷保持 `/vol1/@appdata/qibox`。
- 安装后的前端、原生打开逻辑和服务代码 SHA-256 与已校验安装包一致；安装内容中已无消息定位模块或定位按钮标记。
- 使用已安装服务的正式 API 连续打开“毒药💊”三次，结果均确认账号和联系人身份，耗时分别为 **7960、2239、2015 毫秒**；返回值仅表示聊天已打开，不含定位结果。
- 打开后另行只读检查微信桌面：Bot 的微信主窗口唯一，聊天顶部是“毒药💊”，消息列表可见。
- 本地检查：`npm run check`、Node 单元测试、Python 原生测试及 390px 移动端布局检查通过。首次打开涉及冷启动数据身份核验，约 8 秒；后续打开约 2 秒。此处不承诺消息定位。
