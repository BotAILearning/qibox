# 微信公众号文章菜单点击修复

## 问题与处理

AI 发送中断留下待核验草稿时，远程桌面的按下事件会进入 `input-status` 校验。公众号文章窗口属于当前微信的 `WeChatAppEx` 子进程，原校验只接受微信主窗口，因而返回 unsupported；输入门随后丢弃点击，右上角三个点没有反应。

新增只读的文章窗口命中校验，核对当前微信直接子进程、同一系统用户、官方执行路径、进程启动时间、活动窗口和实际点击区域。核验通过仅返回 `safe: true, resolved: false`，不清除聊天草稿保护，不授权回车发送。未知窗口、其他进程、遮挡、越界、窗口或进程变化继续使用原保护流程。

实际微信子进程不能由服务用户读取 `/proc/exe`，且会把启动选项追加到 argv[0]，因此使用有界读取的 argv[0] 配合上述归属和窗口条件；不记录其余启动参数。

- 本地全部 Node 测试 962 项通过，语法、产品标识及版本检查通过。
- Python 原生输入与新增文章窗口测试共 130 项通过。
- 草稿中断回归测试确认：文章指针可继续操作，待核验草稿及保护标志保持，回车仍被拒绝。
- fnOS 实际设备，栖盒 `0.10.19`、微信 `4.1.13.23`：修复前同一文章点击的原生校验返回 unsupported；修复后返回 `safe: true, resolved: false`。
- 通过实际栖盒浏览器桌面点击三个点，确认菜单打开、点击外部关闭、再次点击重新打开。截图保存在忽略的 `local/article-menu-fixed.png`。
