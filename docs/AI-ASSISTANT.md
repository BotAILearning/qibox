# AI 辅助产品规则

## 自动发送安全原则

- 未确认的发送结果不视为成功，不自动重发，避免重复发送。
- 草稿、未发送内容和未知回执不记为已回复。
- 账号、实例、联系人或会话发生变化时重新核验。
- 用户手动操作时让出控制权；需要文件、电话、图片、视频等外部操作时，不虚构已完成。
- 单条待核对只影响当前回复，不关闭整个自动回复；后续新消息可重新判断，但不重发旧的不确定内容。

## 0.2.0 当前流程

保存模型配置即可开启 AI，总开关不再要求先测试连接、选择对象、学习风格或填写策略。新配置默认处理所有个人联系人的新消息，模型判断是否需要回复；可改为只处理已选择的联系人。已有明确选择范围在升级时保留。微信未就绪时保持开关偏好并等待，切换微信账号仍停用。

后台收消息不依赖打开网页或持续获取界面状态。最近一次明确登录后，界面探测暂时没有结果不会阻断读取；每次仍核对进程、当前账号与数据库版本，明确退出登录立即停止。数据读取使用每个微信进程独立的常驻子进程，密钥和最多 16 份近期查询结果只留在内存，数据库、WAL 或提交版本改变即重新读取，账号切换、停止或清理上下文时释放。最多两个联系人的模型请求并行，实际导航与发送仍串行并逐次核对对象和新增发送回执。默认消息合并等待为 3 秒，用户保存的等待值不在升级时强制覆盖。

联系人回复页面只需选择风格，可编辑文字说明；注意事项、回复目标、已知信息与回复上限放在可选区域。未填写策略时自然回复，填写后执行当前联系人的策略；风格与事实、策略分开传入模型，不能混入其他联系人的数据。

后台每次轮询最多处理两个正在生成或发送的联系人任务，任务执行期间继续读取其他联系人的来信；同一联系人不会重复启动，原生发送仍按顺序执行。原生控件状态使用一次完整状态读取，避免为每个标志重复访问；不减少账号、联系人、前台窗口、聊天变化或发送回执校验。

风格学习输出自然语言总结，允许基于本人历史发言给出称呼与简短例句，例如有证据时总结“称呼对方为宝”。不再限制关系或风格枚举。总结在应用前后均可修改，用户修改内容在后续更新中保留。自动代发的消息 ID 单独记录并排除出学习样本，避免反复学习模型自己的输出。旧枚举格式继续兼容读取。

回复保留必要标点；提示模型在适当时机自然提问，避免每句都追问。禁止模型式自我介绍；身份考验可忽略或只回应其中正常的聊天内容，不编造身份或个人经历。文件、电话等能力外的请求继续交给用户处理。

左侧“待核对”超链接、首页提醒和不确定队列项均可打开核对弹窗。弹窗展示对应联系人的最近文字聊天，并提供跳转到该微信会话的超链接。确认核对时再次校验聊天版本，变化后必须重新查看；恢复仅处理后续新消息，旧的不确定消息不会重发。

主动聊天支持立即执行一次、具体时间执行一次、每日和每周重复。时间按北京时间解释；支持“10分钟后”“明天晚上八点半”“每天上午”“每周五下午3点”等。模糊时段包括上午 09:00–11:30、下午 14:00–17:00、晚上 19:00–21:00。重复模糊时间在每次发生后，为下一次重新随机抽取；例如今天 20:30、明天 20:40。已抽中的下一次时间持久保存，普通重启不重新抽签。精确钟点重复则保持该钟点。

定时任务独立保存联系人和策略。总开关与主动聊天开启、微信就绪且当前队列空闲时执行；关闭期间不发送，重新就绪后到期任务执行一次，不补发每个错过的周期。已开始但中断的队列保持暂停，发送结果未知时待核对。取消定时停止该任务未完成的队列及续聊。模型请求与发送始终绑定账号和联系人 ID，发送前后继续校验对象、聊天变化和数据库回执。

0.2.0 的本地验证和未完成的实机项目见 [本版记录](../reports/AI-WORKFLOW-0.2.0.md)。以下为历史版本行为，当前流程以上述约定为准。

## 用户已经确认的功能

- 微信桌面左侧同时提供「AI 辅助」入口和总开关，普通窗口与全屏保持一致。关闭时仍能进入设置、制定策略和学习。
- 主动聊天、回复策略各有独立开关，关闭总开关时也可以打开配置入口。实际执行仍需完成模型接入、有效策略及对应对象准备；回复策略可手动选择或通过学习获取，主动聊天可使用手动风格或引用已学习风格。
- 自带模型：预设 DeepSeek、通义千问、智谱 GLM、Gemini、Claude、OpenAI、硅基流动，选择服务后填入 API Key；支持自定义地址、接口类型、对话模型和超时。兼容 Chat Completions 与 Anthropic Messages，只直接使用一个对话模型，不进行 Claude 模型映射。拉取列表使用当前填写的配置，不保存草稿或改变已有测试状态；测试连接会保存并验证当前配置。接口不支持列表时可手动填写并测试。列表只过滤明确的非对话模型，最终可用性以测试为准。聊天仅发送到用户选择的模型服务。
- 学习入口：读取微信联系人、单独学习或勾选最多 10 位联系人批量学习；也可以粘贴带发言人标记的聊天。支持取消选择和取消正在进行的学习。
- 分类是参考，可修改；包含亲密关系、家庭亲属、朋友社交、职场协作、商务合作、教育学习、服务事务、社群兴趣、初识关系、自定义与暂未确定。群聊使用独立触发开关与群成员/@元数据，不混作单聊；真实设备适配与群聊流程仍需单独验收。
- 只保存结构化风格，不保存原文、截图、聊天摘要、生成正文或向量库。账号/对象标识、用户填写的策略、开关、任务进度属于必要配置，单独保存。模型返回的风格只能使用预定义枚举；用户可以另行填写风格补充。
- 回复型提供「多轮问答」「智能判断是否回复」「每轮更新风格」开关。学习时分析用户本人对选定联系人的口吻，其他人的消息仅用于理解相处方式。连续消息先合并；更新风格不覆盖用户手动补充。关闭风格更新仍读取本轮上下文。
- 主动型：第一步获取联系人列表并明确勾选对象，配置后启动一次，第一位立即发起；每次成功主动发送后重新随机等待 120–300 秒，再联系队列下一位。只随机间隔，不随机对象顺序，不等待前一位回复。同一队列不重复联系同一对象。
- 已主动联系的对象收到消息后围绕本次聊天目标接续，其他自动回复仅作用于回复策略选择的对象；用户手动发言后暂停该对象的主动发送和自动回复。主动队列与回复任务独立。关闭主动聊天暂停队列并停止其接续回复，关闭总开关取消未发送操作；可以暂停、继续、跳过和结束队列。移除主动对象后，该对象在旧队列中尚未发送的任务跳过，恢复队列时再次核对当前范围。
- 策略包含主动目的、内容、表达方式，以及回复目的、允许使用的信息和不能擅自决定的事项；支持对象专属覆盖。模型不能通过聊天内容改变开关、对象、策略或调用系统工具。
- 群聊触发：已验证且开启的@我触发按当前设置判断send或skip；@所有人和实时触发由模型判断send、skip或请求1–30秒短暂wait，等待期间保留来信，到期重读并重新判断。对方要求停止联系时只skip本轮，不暂停、不转交本人。普通实时消息每60秒合并；不同实时回复轮次至少间隔30秒，@我不等待该周期。群聊没有固定的10分钟条数限制或固定话题轮数限制；连续回复由用户设置的maxRounds控制，范围1–2000。手动接管、用户显式暂停、账号与身份安全保护仍保留；群聊发送结果不确定只记录审计事实，本轮不重发、不要求人工核验，后续新群消息继续处理。仅@他人不参与。实现与本地回归证据见 [群聊触发实现验收](../reports/group-trigger-20260923.md)。

## 0.1.25 联系人列表与批量学习

回复策略开启后直接展示当前可读取的联系人，每位联系人都有独立策略位置；尚未设置的策略留空。每行可单独学习用户本人与该联系人的聊天风格，学习完成后确认应用并设置该人的回复目的、允许信息和限制。单人或批量应用保留其他已配置联系人的策略与回复范围。

每位联系人也可以直接“选择回复策略”，从自然交流、简短直接、礼貌正式、耐心解释等选项开始，调整口吻、补充说明、回复目的、允许信息和限制后应用。手动配置无需学习、无需读取聊天或调用模型；正式自动回复仍需配置并测试模型，然后打开 AI 总开关。手动选择单独保存配置来源，未学习的对象不会冒充学习成果。也可稍后学习该联系人的聊天风格。

批量学习入口打开联系人勾选页面，前后端均限制每批最多 10 位。按联系人读取聊天，将所选资料整合为一次模型请求，分别返回关系类型、表达风格及禁忌。服务端按联系人标识严格对应结果，完整校验后统一保存；缺少、重复、未知联系人或不完整风格不会造成部分应用。每人的资料按相同预算保留最近完整文字消息，合并请求控制在 90000 字符以内。取消或账号变化后不应用迟到结果。

取消标签分组和按风格展示模块，结果按联系人展示。主动聊天的第一步同样获取联系人列表并保留勾选，完成目标、内容与风格设置后，仅对保存的联系人依次发起。已加载联系人时复用当前列表，用户可显式刷新；刷新会暂停正在运行的辅助任务。

联系人发现与聊天内容读取分离，不再以消息区、输入框和发送按钮作为联系人列表的前提；账号读取不再依赖“登录方式”控件。扫描显示联系人读取进度且支持取消。无法获取列表时清除旧联系人，避免旧账号或旧会话对象继续被选择。原生实机适配范围与本版验收结果见对应开发记录。

## 0.1.24 多轮沟通与模型密钥

API Key 保存后在输入框中显示星号，可用「展示 / 隐藏」切换。展示已保存的密钥使用独立的当前用户、当前实例接口；普通设置读取与轮询不返回明文。关闭面板或切换实例后恢复隐藏。星号仅用于显示，不会被提交成新的密钥；切换模型服务后需填写对应密钥。

回复策略的「多轮问答」默认关闭。开启后，模型根据本轮消息和用户已经学习的风格，自行决定发送一条或分为最多三条文字，并可自然提出问题。多轮消息间隔默认随机 2–8 秒，可设置为 1–30 秒内的范围。需要进一步询问时，可安排一次延后追问，默认等待 45–120 秒，可设置为 15–600 秒内的范围；到时重新读取聊天，由模型判断是否仍有必要发送。没有新回复时不会重复安排追问，所有接续均受自动回复轮数上限约束。

主动聊天的「多轮沟通」沿用已配置的聊天目标、内容要求和风格，开场与后续交流都可按需分段、等待及追问；选择单条沟通时每次只发送一条，不追加延后追问。主动沟通和独立回复的开关分别生效，主动聊天的接续始终使用本轮目标。

收到新消息时取消旧的延后追问，转为处理新一轮内容。每段发送前重新核对账号、联系人和上下文；用户接管、关闭开关、暂停、取消、修改策略或范围时取消尚未发送的操作。延后追问仅保存在内存，重启后不会恢复旧追问，也不保存待发正文。

## 0.1.23 AI 辅助流程

配置主页仅保留主动聊天与回复策略两张开关卡，模型设置位于右上角。回复策略开启后显示已经应用的策略和风格；尚无策略时结果区为空，不填充示例或预设学习结果。下方通过“学习风格 / 重新学习风格”进入学习流程。

学习顺序为：拉取可读取的聊天列表、明确选择联系人、读取聊天正文、调用用户已经配置并测试通过的模型、展示模型返回的结构化风格、确认并应用。结果可按风格或联系人展开，关系类型、口吻、禁忌和专属回复策略均可调整。仅学习不会启用自动回复，应用后可通过左侧总开关启用。粘贴未绑定联系人的学习结果可以单独保存并供主动聊天引用。学习进度和取消入口在长任务中持续可用。

主动聊天顺序为：选择对象 → 聊天目标 → 内容与要求 → 风格与人设 → 确认并一键发起。风格可手动输入、从粘贴内容交给模型学习，或直接引用已学习风格；手动配置的对象不计为学习成果。主动对象与回复对象分别保存，通用回复策略、联系人专属回复策略与主动目的分开保存，修改主动配置不会改写已应用的回复范围和信息。历史对象完整专属策略仍保留其显式覆盖，发起前展示对应目标。

主动开场可选单条或最多三条分段发送，每段发送前重新核对对象、账号、上下文和取消状态；已确认的前段不会整组重发。队列显示已发送段数，发送中断或结果不明确时停止剩余分段。已主动联系对象的接续回复保留本轮目标；关闭主动聊天、结束或取消后撤销该接续。

目前原生适配尚不能读取微信标签；标签入口如实显示不可用，用户可返回聊天列表选择，不能将它视为已完成的微信标签集成。真实模型响应质量和完整实机自动聊天仍需部署后验收。本地回归使用可追踪的模型与微信替身，不会向真实联系人发消息。

## 0.1.21 新增交互

主动联系开始前检查有效策略是否有目标、开场要求和限制。提供日常关心、恢复联系、活动邀约、事项跟进、收集意见、沟通时间六种目标模板；套用只修改目标和开场要求，不覆盖用户事实、限制或回复策略。支持自行编辑，专属策略优先，并在开始队列前展示每个对象的有效目标。

当前自动发送仅限文字。对方提出文件、电话、图片或语音等文字操作请求时，模型应说明当前能力边界并提供文字回应；模型不得据此暂停自动回复或转交本人。实际媒体或身份安全检查、用户手动接管和账号变化等独立保护仍按各自规则处理。发送结果无法确认时，私聊与主动聊天保留核验保护且不自动重发；群聊只保留加密审计记录，本轮不重发、不暂停、不要求人工核验，后续新群消息继续处理。对象设置中开启自动回复（群聊为 @我／@所有人／实时回复任一开启）并点击【保存设置】，表示本人要求由 AI 处理后续新消息；保存开启状态可解除普通可恢复暂停，但不能跳过私聊或主动聊天的不确定发送核验。只持久化固定原因码，不保存请求正文。原生读取仍只支持已验证的文字布局；真实媒体气泡或无法确认的布局沿用对应安全规则，不能据此宣称已具备媒体识别能力。

配置参考：[CC Switch 预设流程](https://github.com/farion1231/cc-switch/blob/main/README.md)、[Gemini 兼容接口](https://ai.google.dev/gemini-api/docs/openai)、[阿里云兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)、[Claude 模型列表](https://platform.claude.com/docs/en/api/models/list)。预设可能随服务商更新变化，用户可拉取或自行填写，真实密钥测试仍需部署后完成。

## 执行规则

发送前重新检查当前账号、对象、会话版本、开关和取消信号。上下文变化则重新生成；用户接管则取消。私聊和主动聊天发送结果无法确认时标记待核验并暂停，不自动重发；群聊结果无法确认时标记审计记录、消费本轮且不暂停或重发，之后的新群消息仍可处理。服务重启后保留总开关和回复进度，重新核验当前账号后继续自动回复；旧主动队列、旧追问和私聊/主动聊天发送结果不确定的任务保持暂停。

取消时，如果尚未点击发送，只清理本轮写入、仍在原对象原输入框且内容完全相符的草稿。无法确认清理成功时阻止接下来的桌面输入，关闭 AI 并暂停任务；用户检查输入框后，在 AI 面板点击「恢复手动输入」明确接管。更换对象、输入框或用户改过的草稿不会被猜测删除。

读取、学习和生成使用内存中的聊天内容，不持久化正文。为对齐连续观察，Node 的 `MessageLedger` 在纯内存中保留当前上下文，正文合计最多 4 MiB，每个会话最多 300 项。消息使用本次观察期间的临时 ID，不是微信永久消息 ID，也不按正文哈希当作消息身份。重复内容存在多种对齐方式、历史倒退或无法确认连续性时停止处理，要求重新检测；原生观察的 revision 不被账本替换。

重新扫描、微信进程变化及服务重启后清除账本；关闭、取消和学习结束也会清除内存上下文。关闭/取消同时中止模型及原生操作，迟到的结果不得保存或发送。这些清理路径已通过本地回归测试。外部模型服务自己的留存政策不由栖盒控制。

## 微信适配与验收边界

保持官方微信安装文件和进程原样，不注入、不挂钩、不替换组件，联系人和历史消息现通过只读数据适配读取，详见 WECHAT-DATA.md。所有新增代码、密钥和设置均属于栖盒。用户在远程桌面点击或输入时，自动操作至少让出 15 秒；用户手动发送消息后，暂停该对象的主动发送和自动回复。手动 RFB 键盘、鼠标、滚轮和剪贴板输入送达微信前，服务器先取消原生自动操作，等待其子进程实际关闭，再交接输入；按键或鼠标仍被按住时保持让出。该屏障已接入飞牛 WebSocket 与绿联 HTTP 桌面传输，并通过本地协议及传输回归测试。每次启动原生助手前后重新核对取消信号和微信进程，取消扫描后不得另启恢复会话的操作。

实机已经推翻早期对机器属性的假设：当前官方 Linux 微信没有提供适配器原先假定的 `account-id`、`conversation-id`、`message-id`、`direction` 属性或所需关系信息。这些字段不能再作为已有官方接口描述。

适配器仍通过实例私有桌面的外部接口工作。当前账号从微信设置即时读取微信号并计算哈希；对象从个人资料读取微信号，结合当前账号计算对象标识。0.1.25 从通讯录读取可暴露的联系人条目，不再限制为前 50 位可见会话；昵称仅作为待核验候选，不能作为发送身份。扫描逐项打开并核验个人资料，绑定成功后才提供对象，部分无法核验会提示数量；读取和发送只使用内存中已核验的绑定，发送前再次核对当前账号和对象 ID。群聊、无法取得可靠身份或昵称存在歧义时不发送。

聊天文字由 AT-SPI 读取。消息方向结合实测的 96 DPI 浅色界面普通文本气泡及左右头像区域判断；像素只用于内存中的布局核验，不持久化截图。顶部被裁切的历史项不作为完整消息。媒体消息、群聊、未知布局及无法可靠判断的项目尚不支持，出现时停止自动处理，不能推断成普通文本继续发送。此适配不保证其他主题、缩放比例、客户端版本或全部历史记录可用。

截至 2026-09-14，已在 x86_64 飞牛上对用户指定的「林宝平_Bot」完成真实文本读取和一次外部界面发送；随后通过真实 Node 桥接完成仅限该对象的扫描与两次读取，10 项消息的临时 ID 保持稳定，清理上下文后旧基线失效，后续验证未新增发送。详细证据与范围见 [0.1.20 开发记录](../reports/AI-ASSISTANT-0.1.20.md)。这些结果不能替代多对象扫描、ARM64、真实模型、实机手动接管及完整自动回复流程的验收。用户将在部署后自行配置模型；当前真实模型质量及连通性未测试。
