# 全局界面重设计与 0.9.12 真机验收

日期：2026-09-25。发布性质：fnOS 双架构 Debug 包；UGOS 暂停。

## 改动范围

- `web/ui-foundation.css` 统一按钮、输入框、选择框、数字字段、长文本、表格和卡片的尺寸与间距，覆盖桌面、平板和手机布局。该样式由 `c346617` 及其父提交引入。
- 运行记录收窄「操作」栏，将记录范围与总结并排；窄屏改为分组卡片，长内容可换行。
- 电脑端隐藏首页底部重复的「我的实例」，保留桌面实例图标与操作菜单；手机端继续显示实例列表供登录与管理。
- `web/index.html` 引入统一样式，构建和设备静态文件服务均包含它。本次构建基于已提交的移动登录改进 `91120f9`。

## fnOS x86_64 真机

- 设备 `192.168.3.7` 升级前应用中心登记为 0.9.10、运行文件 `0.9.10-debug.001`。安装前先复制应用数据和程序到 `/vol1/.qibox-preupgrade-0.9.11-debug.001`：应用停止后完成最后同步；备份占用约 78 GB、逻辑大小 53802516210 字节、536273 个普通文件。排除可再建的 `sessions/`；复核时发现符号链接权限位差异，因此不把备份描述为逐字节一致。
- 应用中心依次成功安装 `0.9.11-debug.003` 和最终的 `0.9.12-debug.001`。最终安装卷为 1，系统和 Node.js 依赖匹配，升级前后的 API 权限范围一致。最终设备 `config/product.json`、`public/ui-foundation.css` 和 `public/style.css` 与安装包对应文件哈希一致。服务状态为 running，只有一个主服务进程，应用 Unix socket 可连接。
- 首次升级时出现残留旧进程移除新 socket 的故障；清理旧进程并按应用中心流程重启后恢复。最终升级没有再出现该故障。
- 真机 Chrome 以 Bot（UID 1000）登录，UI 样式请求 200，运行记录 10 行、样例联系人「林宝平_Bot」匹配。1440 像素下行高 115 像素、「打开聊天」按钮宽 116 像素；升级前分别为 147 与 218 像素。系统设置中可见数字框宽 56 像素，升级前为 1130 像素。
- 首页在 1440、390、320 像素，运行记录在 1440、1024、768、390、320 像素，以及 AI 五个主要页面在 1440、390、320 像素均无整页横向溢出、无页面脚本错误。电脑首页不再显示底部「我的实例」，手机首页仍显示实例列表。
- Bot 的「微信」与「微信 2」均在最终升级后重新进入微信。设备 `/api/state` 最终显示两者 `status=running`、`loginStatus=logged-in`、`aiEntryAvailable=true`；未发送聊天消息，也未改动 AI 设置。
