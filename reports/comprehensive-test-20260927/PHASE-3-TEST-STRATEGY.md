# 全面测试阶段三：分层测试策略与通过标准

测试基准：[产品设计规格 v1.6](../../docs/PRODUCT-SPEC-BASELINE-20260927.md)

Astra 输出：60 组用例，P0 16、P1 32、P2 12。参数化变体逐项记结果（如 `P1-08/2001`），不得以用例组名掩盖未测变体。

## 证据等级与数据保护

- **R 只读设备**：已安装 fnOS x86_64；允许脱敏读取状态、页面、运行日志，不改设置或发送消息。
- **T 隔离测试**：专用实例、测试账号/对象或隔离数据副本。真实发送仅使用 `local/REAL-DEVICE-TEST-ACCOUNTS.md` 中授权角色与测试对象；不触碰普通联系人。
- **F 故障注入**：仅在 T 注入延迟、拒绝、断连、进程中断或文件系统故障，不杀生产进程、不断开生产 NAS。
- **B 浏览器模拟**：仅证明浏览器/视口/API 替身覆盖，不证明手机 OS、无线切换、真实 NAS 故障。
- **M 手机真机**：实体手机连接候选，记型号、OS、浏览器、方向、字体设置。
- 每条保存规格版本、源码/包/设备摘要、时间、前置状态、步骤、实际与预期、脱敏截图/日志及清理读回。只清理本轮数据；设置写入前快照，结束时恢复并读回。
- 结果只用：通过、失败、部分验证、阻塞、未测、不适用、规格未决。替身结果不得升级为真机通过。敏感聊天、API Key、凭据不写报告。

## 放行门槛

- P0、P1 全部失败需修复并在受影响的真实设备边界复测；阻塞、未测、规格未决不计通过。
- P2 逐项报告风险、规避和接受依据。未测机型、辅助功能、长稳/弱网项不能外推。
- 统计同时报告“通过/已执行可判定数”和“已执行组数/60”，另列失败、部分验证、阻塞、未测、不适用、规格未决。
- 若真实发送、实体手机或产品语义尚未闭合，最终结论标记为“候选验收未完成”，不能写成全面测试通过。
